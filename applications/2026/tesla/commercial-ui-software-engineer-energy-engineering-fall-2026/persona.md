# Recruiter Persona: Internship, Commercial UI Software Engineer, Energy Engineering (Fall 2026)

## Role Summary

This is a Fall 2026 onsite Tesla Energy internship for a full-stack UI/software engineer working on production systems that monitor, aggregate, and control real-time data from large IoT device fleets. The JD surface is web and distributed systems: JavaScript/TypeScript, Node.js, React, code quality, performance, reliability, security, and testing. The company identity adds an EV/energy-systems flavor: software that touches real-world infrastructure, not a generic dashboard.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** EV/energy IoT systems
- **track_divergence:** true

The resume spine should read as full-stack software engineering: shipped product surfaces, backend services, APIs, data stores, and frontend depth. The company-fit signal is the ability to reason about real-time systems, device-adjacent reliability, and production control surfaces. The blend is full-stack first, with EV/energy-style operational discipline visible early.

## Team & Bar

Tesla screens for interns who can move quickly without treating quality as optional. For this role, the bar is not "frontend-only"; it is a production software screen for systems that handle real-time and streaming data from many devices. Strong evidence looks like shipped full-stack systems, live data paths, performance/scalability work, testing or reliability discipline, and enough frontend specificity that React/TypeScript is believable rather than a skills-line claim.

The funnel is a selective B-tier big-tech-style process: resume screen, likely HackerRank OA, and technical rounds around medium coding plus practical engineering depth. A strong screen is concise, ATS-clean, and immediately shows the JD languages through real use.

## Screen Criteria

- JavaScript/TypeScript, Node.js, React, and preferably GraphQL must appear as demonstrated tools, not just skills-list decoration.
- Full-stack evidence should include both user-facing/client work and backend or data-flow decisions.
- Real-time, streaming, event-driven, IoT, or device-adjacent systems are valuable company-fit signals when placed near the top.
- Production discipline matters: performance, scalability, reliability, security, testing, or deployment decisions should be attached to concrete systems.
- Anti-patterns: generic club operations with no engineering depth, notebook-style ML with no shipped surface, robotics-only framing that obscures the web stack, and frontend claims with no actual React/UI architecture.
