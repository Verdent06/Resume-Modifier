## Role Summary
You join ICER to help researchers get code running on MSU’s HPCC with less confusion: the core deliverable is an LLM-based agent that assists with submission workflows, backed by a maintained repo and real evaluation—not a demo. Day to day you pair with ICER staff on agent design and implementation, keep the codebase collaboration-friendly, build schemas and harnesses to test whether the agent is right about code it reviews, log how it behaves on realistic tasks, and summarize findings for ICER leadership and MSU research forums. At three months, success looks like a reproducible dev loop (issues/PRs, tests, small experiments with clear metrics) and a first credible slice of evaluation data the team trusts enough to discuss internally.

## What They're Really Looking For
- A strong Python engineer who is comfortable on the command line and in a shared Unix-style environment, because HPC workflows are inherently CLI- and batch-oriented even if the agent has a friendly surface.
- Someone who treats LLMs as components to instrument and validate, not magic—schemas, test cases, and failure modes matter as much as prompts.
- Evidence you can own a software repository with others: branching, review, incremental delivery, and documentation that another student can pick up next semester.
- Curiosity about *measurement*: gathering performance/accuracy signals and explaining them clearly to technical non-ML stakeholders.
- Self-direction with low drama: ICER will give direction, but they want you to unblock yourself using docs, forums, and LLM tooling—then bring questions when you’re stuck for real.
- Interest in research-style communication (posters/talks/internal readouts), not only commits.
