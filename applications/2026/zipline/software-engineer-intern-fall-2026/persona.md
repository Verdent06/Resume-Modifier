- Full-stack evidence through bullets: mobile or web client work, backend APIs/services, and deployment — not Skills-line keyword stuffing alone.
- Python and Go should appear in project or experience context where the JD languages are named; React Native or strong React/TypeScript client depth supports the mobile/web mandate.
- Strong signals: end-to-end feature ownership, product-minded trade-offs, polyglot backend depth, measurable user or operational impact, and real-world systems discipline (reliability, safety boundaries, hardware-software integration).
- Anti-patterns: notebook-only ML without delivery, club-growth narrative without engineering depth, generic technology lists, and a page that reads purely as robotics research with no consumer/product engineering surface.
- When track diverges, the first-read should still say "ships product software" while a secondary read registers autonomy or real-world systems depth.
