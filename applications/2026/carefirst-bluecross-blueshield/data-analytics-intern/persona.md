# Data Analytics Intern at CareFirst BlueCross BlueShield

## Role Summary

CareFirst is screening for a year-round Data Analytics Intern in Client Reporting and Analytics, not a general software engineering intern. The intern extracts and integrates data from multiple systems, completes ad hoc and production analyses, develops dashboards and scorecards, contributes to account reporting and healthcare quality/cost-of-care work, and documents project output for business stakeholders. The JD surface is analytics and visualization; the company identity is healthcare operations and member/provider outcome analytics.

## Track Decision

- **screen_track:** ai-ml
- **differentiator:** healthcare-analytics
- **track_divergence:** false

This should read as a data/analytics resume: SQL, Python/R, databases, visualization, statistical or model-adjacent work, and clear stakeholder-facing reporting. General full-stack systems depth is useful only when it proves data extraction, data modeling, or analytics delivery.

## Team & Bar

The screen is likely handled by a recruiter or analytics manager looking for an eligible student who can learn in a fast-paced healthcare data environment. The bar is practical: demonstrate beginner-to-intermediate data tooling, clean analytical thinking, comfort with relational databases, and the ability to explain technical findings to non-engineering stakeholders. Because this is a year-round internship, availability, location eligibility, GPA, and sponsorship status are hard early filters.

## Screen Criteria

- SQL and relational database work should appear in bullets, not only in Technical Skills.
- Python or R should be visible as a real analysis/programming tool if possible.
- Dashboard, visualization, reporting, or stakeholder-facing delivery is a strong fit signal.
- Healthcare domain experience is not required, but business-facing analytics and documentation should be easy to infer.
- Pure robotics/autonomy or club-growth framing without data/analytics evidence reads off-axis.
- Generic software projects should be framed around data extraction, integration, database design, reporting, or measurable operational insight.
- Communication and documentation matter because the role supports project stakeholders and business partners.
