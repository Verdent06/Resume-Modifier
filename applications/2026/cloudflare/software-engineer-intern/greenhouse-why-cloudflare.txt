What pulls me toward Cloudflare is that the whole company is built around the problem I keep gravitating to on my own: making software fast at the layer where latency is unforgiving. My favorite project is a granular synthesizer I wrote from scratch in C++/JUCE, where the audio thread can't allocate memory or take a lock without causing an audible glitch. I hand-rolled a single-producer/single-consumer FIFO with acquire/release atomics to move parameter changes from the UI thread to the audio thread without a mutex, and pre-allocated a fixed MemoryPool<Grain, 64> per voice so processBlock() never touches the heap after startup. That's the same discipline Cloudflare Workers runs on when code has to execute at hundreds of edge locations inside a single-digit-millisecond budget with no room for a slow path.

I've also learned I like this work at both ends of the stack. At CaseStudyPrep.AI I moved audio processing off the UI thread into a Web Worker to keep main-thread blocking under 5ms, and ran Silero VAD client-side via ONNX Runtime to cut cloud inference costs 40% by never shipping dead air. On my own I've shipped and operated production systems: Vylet, a Dockerized LangGraph lead-sourcing pipeline with Redis/Celery workers that I've grown to $1,500 MRR across three paying clients, and SignalWeaver, a FastAPI + pgvector service I instrumented down to 49ms p50 semantic search, fronted by a React/TypeScript dashboard and deployed with Docker Compose and a GitHub Actions CI pipeline.

The product I'd most want to build on is the Workers developer platform: the serverless edge runtime and the primitives around it like Durable Objects, KV, and R2. It sits exactly where my full-stack shipping habit and my low-latency systems instinct overlap: a developer surface that has to stay simple while the runtime underneath fights for every millisecond. I'll be honest that my systems work has been in C++ rather than Go or Rust so far, but the lock-free, zero-allocation reasoning transfers directly, and ramping onto Cloudflare's stack is exactly the kind of work I'm looking for.
