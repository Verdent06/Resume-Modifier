# Software Engineer Intern (Fall 2026) at Cloudflare

## Role Summary

Cloudflare hires a Fall 2026 Software Engineer Intern into an Austin, TX hybrid role (in office 3–5 days/week, full-time 40 hrs/week for a 12–14 week project). The intern ships and delivers a scoped project end-to-end with autonomy plus support, works cross-functionally, pairs closely with a mentor, presents the final project to the entire company, and may write for the Cloudflare blog or Cloudflare.tv. The JD's *requirements* are generic SWE — currently pursuing CS/Engineering/Math/Statistics, critical thinking, drive to learn — with a polyglot language list (TypeScript, JavaScript, Go, Rust, C++, Python). Company *identity* is low-latency systems at the edge: a global network running CDN, DNS, DDoS/Zero Trust security, and the Workers serverless developer platform where Go/Rust are first-class and systems fluency is valued.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** systems / edge (low-latency systems; Go/Rust/C++ engineering identity)
- **track_divergence:** true

The JD's requirements are a generic Software Engineer Intern spec plus a polyglot language list — not a systems/infra job description — so the resume spine must pass a full-stack SWE screen: shipped products with real users, backend APIs, client surfaces, cloud/Docker/CI, and JD languages demonstrated in bullets rather than a Skills list. Because Cloudflare's engineering identity is performance-critical edge systems, the page must also register genuine low-latency/systems depth (concurrency, memory discipline, real-time constraints, C++/systems reasoning) prominently in the top half. On a 7-second scan the resume should read "ships full-stack product software," and a parallel read should register real systems engineering — it must not collapse to either pole. Go and Rust are JD-listed but candidate-absent; they are a legitimate out-of-rails gap to record honestly, never to fabricate.

## Team & Bar

The reader is a systems-literate Cloudflare engineer or recruiter screening a very high-volume funnel (250K+ applications against ~1,111 intern targets; school-blind), so the resume screen is the binding bottleneck. Downstream is a practical/systems loop — HackerRank or take-home, then technical rounds with pair programming and real debugging (`recruiting.md` Part III: the systems-adjacent bar rewards C++/concurrency reasoning and defensible engineering decisions). The bar is evidence of independently shipped software with real users AND demonstrable systems depth in at least one entry: low-latency work, lock-free/concurrent design, memory management, real-time constraints, or measured latency/throughput wins. Polyglot breadth matters, but breadth without a deep, defensible systems bullet reads as generalist. No visa sponsorship is an application knockout handled at apply time, not something inferred from the page.

## Screen Criteria

- Full-stack evidence through bullets: shipped applications with real users, backend services/REST APIs, client or dashboard surfaces, cloud deployment (AWS, Docker, CI) — not Skills-only keyword stuffing.
- Systems/edge depth in the top half: at least one entry with hard low-latency, concurrency, lock-free, memory-pool, real-time, or measured latency/throughput engineering — the signal that makes a candidate memorable past the generic screen.
- JD languages demonstrated in bullets (C++, Python, TypeScript in project/experience context), not listed in Skills alone; polyglot breadth is a plus but depth in one systems layer is the differentiator.
- Strong signals: self-built products with paying users or institutional delivery, sole-engineer ownership, quantified impact metrics (latency, throughput, cost, scale), release-quality artifacts, open-source / personal-project / developer-platform initiative.
- Anti-patterns: systems keywords in Skills with no bullet decision behind them; single-bullet thin entries; club-ops or growth framing without engineering substance; a full-stack spine that buries the systems differentiator at the bottom of the page; notebook-only ML with no delivery.
- When the track diverges, first read says "ships full-stack product software" while the top half also proves low-latency/systems engineering — neither pole alone passes this screen.
