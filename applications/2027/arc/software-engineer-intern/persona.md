# Software Engineering Intern at Arc (Arc Boat Company)

## Role Summary

A Summer 2027 (June 14–August 20), full-time onsite software internship at Arc’s Torrance HQ. The intern contributes to the boat infotainment unit, mobile app, backend, or boat firmware, and is expected to own a project end-to-end in a small, fast hardware startup. The JD surface is generic SWE: one general-purpose language, git/IDE/CLI, fundamentals, communication. Bonus lanes are frontend/mobile, backend Python or TypeScript + AWS, or STM32 firmware. Arc’s company identity is electric marine hardware — software that ships next to a physical boat, not a generic CRUD rotation.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** electric-marine / hardware-adjacent physical product (infotainment + firmware)
- **track_divergence:** true

The literal screen tests enrolled SWE fundamentals and a general-purpose language — not ML frameworks, ROS, or STM32-as-required — so the resume spine is full-stack/general SWE. Arc’s memorable company-fit signal is product software that has to work on a boat: real-time / systems / hardware-adjacent evidence plus shipped frontend or Python/TypeScript+AWS backend. The resume leads with the full-stack spine and keeps real-time C++ / hardware-adjacent evidence prominent and deep — it does not collapse into an STM32 firmware specialist or a PE-sourcing GTM page.

## Team & Bar

The reviewer is screening a B-tier hardware-startup intern cohort on Greenhouse before an unpublished practical loop (~5–10%; bottleneck: resume). They reward evidence that the candidate ships software others depend on, owns a project end-to-end, and can operate next to physical product constraints. Strong signals: Python and TypeScript demonstrated inside bullets (bonus backend); a real frontend (not Skills-only React); C++ under a hard real-time constraint as the firmware analog; production delivery with clear ownership; debugging with before/after numbers; git/CLI implied by shipped repos. They do not need STM32, a boating résumé, or a prior marine internship.

## Screen Criteria

- Demonstrates at least one general-purpose language through use in bullets — Python and TypeScript especially, given the bonus backend line — not only in the Skills list.
- Shows general SWE delivery: frontend or mobile-adjacent product UI, backend APIs/services, cloud (AWS named on the JD), and end-to-end ownership of something used by others.
- Keeps real-time / systems / hardware-adjacent evidence visible in Projects (the company-fit differentiator) without turning the page into a narrow MCU specialist or claiming STM32 the pool does not have.
- Uses impact metrics (latency, failure recovery, speedup, scale, qualification rate) rather than vanity counts or club-ops filler.
- Anti-patterns: leading with LoRA / LangGraph / agentic-PE framing as if this were an ML intern; skills-list keyword stuffing with STM32 or React Native and no backing bullet; a resume that reads purely web with zero systems/real-time adjacency at a boat OEM; deal-sourcing GTM as the lead story.
