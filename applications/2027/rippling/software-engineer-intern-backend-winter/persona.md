# Software Engineer Intern - Backend Focused - Winter 2027 at Rippling

## Role Summary

Winter 2027 Software Engineer Intern, backend-focused, San Francisco (hybrid 3 in / 2 remote; not remote), mid-January through April, 13 weeks. Interns join a product team (user-facing or internal) or platform engineering and ship production backend on Rippling’s compound HR/IT/Finance platform — server-side systems sharing one employee graph. JD surface is generic backend SWE intern: prior SWE intern/co-op using Python, enrolled BS/MS CS graduating after the term, backend programming, cross-functional communication, adaptability. Company identity is the compound workforce platform / employee-graph backend, not a single-product HRIS and not full-stack web fundamentals.

## Track Decision

- **screen_track:** full-stack (backend-focused generic SWE intern: Python backend shipping, APIs/services, production ownership — `resume.md` Part III §12, `recruiting.md` Part III §11)
- **differentiator:** compound HR/IT/Finance workforce platform / employee-graph backend
- **track_divergence:** true

The literal requirements test general SWE / backend fundamentals — prior Python intern/co-op, backend emphasis, communication — not an ML-training filter, not SRE/Kubernetes, not robotics, and **not** a JS/HTML/CSS web-fundamentals floor (that round exists on full-stack Rippling intern reqs; this posting is backend-focused). Rippling’s memorable identity is backend on a shared employee graph (`companies.md` A-tier Notes; `company.md`). Spine is Python backend shipping (services, REST/APIs, production ownership). Differentiator stays prominent and deep: multi-entity data models, production APIs, platform-shaped backend — without inventing HRIS/payroll/App Studio experience. Do not collapse into a frontend page, a notebook-ML / agentic-product page, or a DSP-only systems page.

## Team & Bar

A-tier, ~2–5% **[directional]**; intern funnel in `companies.md` is **Rippling ATS resume → HackerRank OA (4 MCQ + 2–3 coding, Med–Hard DSA, often within days) → 1–2 live HackerRank tech (60 min); bottleneck = OA**. Recruiter voice: an intern who already shipped Python backend in a titled intern/co-op, can own a 13-week production project, and will clear Med–Hard DSA. Strong signals: Python used inside architectural decisions in bullets (not Skills-only); prior intern/co-op using Python; shipped services/APIs with production ownership; DS&A coursework visible for the OA. Behavioral is a filter (`recruiting.md` §6). Encouragement clause: incomplete requirement match is not an auto-knockout, but Python-in-bullets plus a titled intern/co-op remains the bar signal. Eligibility is computed: currently enrolled, `Expected May 2028` is after April 2027 (junior-year winter, returns to school). Hybrid SF 3/2 is a logistics gate, not a resume-content gate.

## Screen Criteria

- Python demonstrated **in bullets**, not Skills alone — the JD’s only named language and a prior-intern/co-op-using-Python floor signal.
- Prior titled internship or co-op in software engineering (or equivalently scoped production delivery) visible on the page; Python used in that work is the strongest read of the JD requirement.
- Backend spine: server-side services, REST/APIs, data stores, deploy path — not frontend-only, not notebook ML (`resume.md` §12, backend-weighted).
- Production ownership a recruiter can size in 30 seconds (shipped API, sole-engineer delivery, before/after reliability or throughput) — maps to “full-time engineer responsibilities” and a scoped intern project with business impact.
- Compound-platform / employee-graph differentiator: multi-entity data, production APIs, or platform-shaped backend visible in the top half — without fabricating Rippling products (HRIS, payroll, App Studio, Travel).
- Cross-functional or stakeholder delivery in at least one entry — the JD names communication across departments.
- CS fundamentals on the page (DS&A coursework; software-design decisions in bullets) — the OA is Med–Hard DSA and is the funnel bottleneck.
- Class-year on page: `Expected May 2028` satisfies graduating after Winter 2027; internship term is junior-year winter with return to school.
- Languages and backend keywords appear through use. Do not treat JavaScript/HTML/CSS as a screen floor for this backend-focused req.

## Anti-Patterns

- Python only on the Skills line with no bullet evidence.
- No titled intern/co-op (or production-equivalent) on the page when the JD lists prior SWE intern/co-op using Python as a requirement.
- Leading with LoRA / LangGraph / agentic-AI product framing as if this were an ML internship.
- Leading with GTM/quant deal-sourcing or club-ops with no engineering the role tests.
- Frontend-only or DSP/plugin-only C++ as the lead story for a Python backend intern.
- Invented Rippling-product experience (HRIS, payroll, App Studio, corporate card, Travel, Help Center).
- Thin single-bullet filler that dilutes a Python-backend + production spine.
- JS/HTML/CSS stuffed to mimic the full-stack intern loop — this posting does not test web fundamentals.
