# Software Engineer Intern at Wedge

## Role Summary

This is a Summer 2027 software engineering internship in San Francisco (with remote leeway) at a YC S25 healthcare AI startup deploying, governing, and scaling AI agents across health systems. The JD surface is general software engineering: design and maintain systems supporting AI agent deployment, write and test code, build back-end services and APIs, debug issues, and improve performance, reliability, and security alongside the engineering team. Wedge's company identity is agentic AI in regulated healthcare — forward-deployed engineering, workflow automation, and a trust layer for health institutions.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** agentic AI / healthcare AI agents
- **track_divergence:** true

The screen spine is full-stack/general SWE because required qualifications test CS fundamentals, DS&A, at least one modern language (Python/Java/Go/TypeScript), back-end web development (APIs, databases, web frameworks), OOP, and Git — not ML training or research credentials. The differentiator is agentic AI in healthcare operations, so the strongest resume still needs visible evidence of shipped agent pipelines, eval/governance discipline, and production-minded backend/cloud work without turning the page into pure ML research.

## Team & Bar

The reviewer is screening for a small YC-backed startup where interns contribute to real back-end services supporting AI agent deployment in healthcare settings. The bar is evidence the candidate can write, test, and debug production-oriented code — APIs, databases, web frameworks — and collaborate on performance, reliability, and security. Strong signals include Python demonstrated through backend/product bullets, REST or service-layer ownership, database and framework evidence through use, Git and cloud/containerization tied to delivery, and agentic-AI work that reads as engineered systems rather than prompt experiments.

## Screen Criteria

- Demonstrates Python (and ideally TypeScript) through backend or product bullets, not only in the skills line.
- Shows back-end web development: APIs, databases, web frameworks, and debugging/performance stories with metrics.
- Ties Git, cloud, or containerization to real delivery — CI/CD, Docker deployment, AWS provisioning.
- Keeps agentic-AI / production-pipeline evidence visible in the top half without burying the full-stack spine.
- Uses quantified impact (latency, throughput, scale, reliability) so "performance and reliability" reads as measured engineering.
- Avoids tutorial-grade projects, vague AI claims without system depth, or entries that lack engineering substance.
