# 2027 Undergrad Software Engineer Intern/Co-op at AMD (req 90891)

## Role Summary

A paid undergrad SWE intern/co-op at AMD in San Jose or Santa Clara (full-time 40 hrs/week, hybrid or onsite). Comp is USD $64,064–$96,096/yr. Terms include Spring/Summer co-op, a summer semester internship (May 24–Aug 13 2027), and Summer/Fall co-op. The posting is a catch-all early-career pipeline, not a single driver or RTL team: work is build/maintain software applications, full SDLC (design, build, test, deploy), automation scripts, debugging, and occasional tech/functional docs. Company identity is CPU/GPU silicon competing with NVIDIA — Ryzen, EPYC, Radeon, Instinct — while this seat is **B for SWE, not chip engineering**. The page should read as a software engineer who can ship and debug next to hardware, not as a web-only intern or a fabricated CPU-architecture specialist.

## Track Decision

- **screen_track:** full-stack (general SWE)
- **differentiator:** semiconductor / CPU-adjacent systems (C++ performance, real-time or embedded-adjacent discipline, production software next to silicon — not RTL, firmware internships, or GPU-kernel work)
- **track_divergence:** true

The literal requirements test current-student undergrad CE/EE/CS status and encouraged (not required) use of listed languages and tools. That is a general SWE screen (`recruiting.md` Part III §11; `resume.md` Part III §12), so the resume spine is full-stack: shipped applications, APIs, data systems, Python/SQL/JavaScript-family delivery, Git, test/debug. They do not name ML training frameworks, ROS, or Kubernetes as a floor, so the spine is not `ai-ml`, `robotics`, or `dev-ops`. The company-fit signal is software that has to be correct next to CPUs — C++ memory/concurrency/real-time constraints, debugging, Linux-adjacent tooling — without fabricating Azure, Java, Perl, PowerShell, Django/Rails/Spring Boot, MongoDB, MySQL, Perforce, UML, or PC-architecture internships. Lead with the full-stack spine and keep C++ systems / embedded-adjacent evidence prominent and deep.

## Team & Bar

The reviewer is a B-tier semiconductor-company university recruiter (AMD careers; 3–4 rounds; Medium; no standard OA in `companies.md`; bottleneck: tech rounds; ~5–8%). They route a generic intern resume onto an applications, tools, or platform-software team. What wins on paper: listed languages shown inside bullets, not Skills alone; a shipped application or data pipeline with ownership and impact metrics; visible test/debug; and enough C++/systems discipline to be believable next to CPUs. Recruiter voice is "can this person write, debug, and ship software at a chip company?" — not "did they intern on a CPU pipeline." Prestige is a tiebreaker (`recruiting.md` §8). Enrollment at a US-based university in undergrad CE/EE/CS (or related) is a hard gate; no visa sponsorship is a knockout on the form, not a resume line. After the PDF, Medium coding plus project/debug depth is the binding filter.

## Screen Criteria

- Demonstrates JD languages through use in bullets — especially Python and C++, plus SQL or JavaScript-family where the work actually used them — not Skills-list only. Java, Perl, PowerShell, Azure, Django/Rails/Spring Boot, MongoDB, MySQL, Perforce, UML are encouraged optionals; absence is not a fabrication invitation.
- Shows shipped application, API, or data-system delivery (REST, ETL, databases, automation, test/debug, production ownership) so the generic SWE / applications routing is obvious.
- Keeps C++ systems / performance / memory / concurrency / real-time or embedded-adjacent evidence visible in the top half as the semiconductor differentiator, framed as engineering tools or systems software — never as an invented CPU-architecture, firmware, or RTL internship.
- Uses impact metrics (latency, cost, failure recovery, scale, hours saved) rather than vanity counts.
- Anti-patterns: claiming Azure/Java/Perl/PowerShell/Django/firmware/CPU-microarchitecture the page cannot defend; a pure agentic/LLM product resume with no systems or application delivery; notebook ML; club-ops filler; burying the C++/systems signal below the fold at a chip company.
