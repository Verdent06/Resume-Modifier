# Software Development Engineer Intern — Summer 2027 at ID.me

## Role Summary

A paid, 12-week, 40-hour, **5-days/week onsite** SDE internship in ID.me's Mountain View office (May or June 2027 start; $60–$70/hr plus possible housing stipend). The intern designs, builds, and tests software under senior engineers; ships **API-first services** used by internal and external teams; joins code reviews, design discussions, and agile ceremonies; writes maintainable code; helps troubleshoot development and production; and learns security, testing, and observability on a platform company. The JD surface is generic intern SWE: one of Java / JavaScript / Go / Python / Ruby, DS&A, OOP. Preferred extras: REST, Git, a cloud (AWS / GCP / Azure), platform/API/devtools interest, and **applied** AI/LLM (RAG, prompt engineering, function/tool-calling) — illustrated by intern example projects (shop.id.me conversational widget; LLM Slack agent for Shop Ops). Company identity is a NIST 800-63-3 IAL2/AAL2 digital identity wallet at government/healthcare/consumer scale, not a research lab and not a generic consumer social app.

- **differentiator:** NIST-grade digital identity wallet / API-first identity platform (applied-LLM intern project examples on shop.id.me / Shop Ops)
- **track_divergence:** false

The differentiator sharpens *within* full-stack toward production APIs, production debug, and **applied** LLM pipelines/agents if the page can carry them honestly — not LoRA notebooks, not identity-protocol research, not a claim of having built a credential service. ## Screen Criteria

- At least one JD language (Python or JavaScript-family/TypeScript) demonstrated **through use in bullets**, not asserted on a Skills line alone (`resume.md` Part I keyword-through-use; Part III §12).
- Shipped, defensible product: backend/API + deploy/cloud + tests or CI, with trade-offs the candidate can narrate — not a tutorial clone (`resume.md` §12; `recruiting.md` §11).
- Production troubleshooting: a named defect or recovery story, matching the JD's "help troubleshoot issues in development and production."
- REST / client-server and Git through use (preferred, but treated as floor signals at an API-first platform).
- Applied LLM, if present, as **pipelines/agents/retrieval in production-shaped systems** (eval gates, embeddings, orchestration) — not ML-research framing, not `model.fit()` notebooks (`recruiting.md` §13 applied vs research).
- Engineering fundamentals visible on the page (APIs, data model, production) so the 7-second scan reads "can ship API-first services," not "ML researcher" or "club ops."
- Class-year on page shows current enrollment (`Expected May 2028` clears the 2028-or-later knockout).

## Anti-Patterns

- Inventing Java, Go, Ruby, Azure, GCP, Snowflake, Databricks, Tableau, Copilot, Fusion, Sentry, or ID.me wallet/NIST implementation experience.
- Skills-list Python (or TypeScript) with no bullet evidence — a floor-signal miss where "demonstrable proficiency" is the minimum qualification.
- Leading with LoRA / held-out-accuracy / return-prediction research when the intern examples are applied chat widgets and Slack agents.
- Club-ops or membership padding with no engineering the role tests (`resume.md` §8).
- Notebook ML or quant-only spine with no shipped API a recruiter can picture as an ID.me platform contribution.
- Two-page or ATS-broken formatting (`resume.md` Part I).
