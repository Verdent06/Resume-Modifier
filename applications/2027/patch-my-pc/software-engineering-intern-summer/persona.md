**Pass signals (abstract):**

- Customer-facing product from API to UI: a backend/API (REST / HTTP / JSON), a frontend framework, and a datastore or deploy/CI path demonstrated in bullets — not Skills-only (`resume.md` §12). Breadth across the stack plus depth in at least one layer.

- Evidence of shipping to a real user or customer (production features, a named bug fix, in-portal-style feedback analog) over club-ops or GTM-only lead stories.
- CS fundamentals visible (OOP, data structures, algorithms) in how systems are described — not a coursework dump.
- Class-year on page shows current enrollment (`Expected May 2028` → Spring 2028; eligible). US live + no-sponsorship auth and Castle Rock onsite are form knockouts, not resume lines.

**Anti-patterns:**

- Skills-list C# / .NET / ASP.NET / Azure / Kubernetes with zero bullet evidence (fabrication smell at a C# shop).
- Invented **C# / .NET** (or Azure DevOps / Intune / ConfigMgr as prior work).
- Routing the page to research-only LoRA / notebook ML because the JD mentions AI interest.
- Lead entry that is off-axis for product web engineering (pure GTM scoring, low-level DSP with no API/UI spine) while the full-stack shipping story is buried.
- Thin single-bullet filler that dilutes a shippable production-product story.
- Club-ops without engineering depth (`resume.md` §8).
- Keyword stuffing patch management / Intune / ConfigMgr in Skills with no supporting system.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
