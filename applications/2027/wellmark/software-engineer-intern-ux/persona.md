## Screen Criteria (abstract)

Pass signals:
- Shipped UI / full-stack product: frontend framework + API or service + persistence, a real user, deploy analog (`resume.md` §12). Keyword-through-use for TypeScript, Angular, SQL, C++, HTML/CSS, Git — not Skills alone (`resume.md` §2).
- Polyglot proof in bullets for JD *or* languages the page can defend (TypeScript, C++, SQL). Angular through use is a strong floor signal for this UX team.
- Troubleshooting / RCA analog: production or user-facing defect, investigation, fix, witness metric — the JD's application-operations support line.
- Shared-code / documentation / source-control discipline visible in how the work shipped (PR, review, usage docs) — not a "Git" Skills token.
- Metrics that size impact (latency, error-rate, hours saved, user-facing wait), landed as the closer (`resume.md` §4).
- Class-year on the page: `Expected May 2028` — honest; do not rewrite standing to "junior" to paper over the computed ambiguity.

Anti-patterns:
- Inventing .NET, Java, Snowflake, Databricks, Copilot, Fusion, Tableau, Kubernetes, or Terraform.
- Claiming Angular, TypeScript, C++, or SQL only in Skills with zero bullet evidence at a company where the *or* list is the technology floor (`resume.md` §2).
- ML-research framing: LoRA-as-lead, publications, notebook `model.fit()` with no application, no UI, no delivery (`recruiting.md` §13 research vs applied split). This req is UX engineering + app support.
- Off-axis lead: pure audio-DSP, club-ops, or agent/RAG-as-the-job when the role tests UI artifacts + shared-code + RCA.
- Claiming Wellmark, BCBS, payer, or healthcare-insurance internships the page cannot defend.
- Metric-free architecture bullets the recruiter cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
