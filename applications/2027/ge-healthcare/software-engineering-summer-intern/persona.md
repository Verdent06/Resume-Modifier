# Software Engineering Summer Intern 2027 at GE HealthCare

## Role Summary

A paid Summer 2027 onsite software internship at GE HealthCare's Salt Lake City OEC Medical Systems site (Surgery Imaging / mobile C-arm). The intern works with senior engineers across the product-development life cycle on software for Surgery Imaging products: automated test frameworks and regression detection on imaging sub-components, defect triage with root-cause and fix, verification and validation of software design and requirements, engineering builds and testing, reliability analysis, peer code reviews, and design/requirements documentation. Surface work is generic intern SWE (implement, test, document, integrate). Company identity is regulated medical-device imaging software that has to be correct in an OR context — not a consumer web product, not GE Vernova, not GE Aerospace, and not the Waukesha EEDP Software intern pipeline (that sibling names Java/C++/Python; this JD names none).

## Team & Bar

The reviewer is a B-tier medical-device university recruiter (Workday; 2–3 Easy–Med practical rounds; no standard intern OA on this packet; bottleneck: resume; ~10–15%, peer Medtronic / GE Aerospace / GE Vernova). They route a generic intern resume onto a Surgery Imaging software team whose day-to-day is test frameworks, defect triage, and V&V — not a greenfield app team and not EEDP. What wins: a shipped application or data pipeline with ownership and impact metrics; test/debug/defect evidence (failure recovery, root-cause, automated tests/CI) in bullets, not Skills alone; enough C++/systems and reliability discipline to be believable next to regulated imaging products. Recruiter voice is practical — "can this person write, test, debug, and ship software?" — not "did they intern on a C-arm." Prestige is a tiebreaker (`recruiting.md` §8). GPA 3.0, sophomore-year minimum, and no-sponsorship work auth are knockout gates, not resume lines.

## Screen Criteria

- Shows shipped application or data-system delivery (APIs, ETL, databases, production ownership, cloud) so the general-SWE screen is obvious.
- Demonstrates test/debug/defect-triage evidence through use — failure recovery, root-cause, automated test or CI, verification-style checking — not a Skills-list "testing" token.
- Keeps C++ systems / performance / memory / concurrency / real-time-safety evidence visible in the top half as the medical-device differentiator, framed as tools or real-time system software — never as an invented C-arm, firmware, or device internship.
- Uses impact metrics (latency, cost, failure recovery, scale, hours saved) rather than vanity counts.
- Anti-patterns: claiming surgery-imaging, Java, C-arm, Snowflake, Databricks, Tableau, Copilot, Fusion, or embedded-firmware internships the page cannot defend; a pure agentic/LLM product resume with no application delivery or test/debug; notebook ML; club-ops filler; burying test/debug or C++-systems signal below the fold.
