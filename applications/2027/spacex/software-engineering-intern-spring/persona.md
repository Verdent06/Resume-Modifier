# Spring 2027 Software Engineering Internship/Co-op at SpaceX

## Role Summary

A Spring 2027 software internship/co-op: paid, full-time onsite, minimum 12 consecutive weeks beginning January or March 2027, flexible across any SpaceX site (Bastrop TX; Brownsville TX; Cape Canaveral FL; Hawthorne CA; Irvine CA; McGregor TX; Palo Alto CA; Redmond WA). The intern works with a mentor on high-impact software for vehicle (Dragon, Falcon, Starship), satellite / constellation (Starlink, Starshield), or SpaceXAI-adjacent programs — aerospace experience is explicitly not required. Comp is class-year banded (Freshman/Sophomore $30/hr through PhD $40/hr); relocation stipend possible; medical; 401(k); paid holidays. The JD surface is generic SWE: enrollment in a bachelor's or graduate program, 3+ months coding experience, and fluency in one or more of C, C++, C#, Java, JavaScript, Python, plus preferred signals around real-world deployment, computer architecture/networks, documentation/requirements, debugging/performance/unit testing, and collaborative ownership. SpaceX's company identity is mission-critical aerospace systems — C++/Python depth, embedded-adjacent rigor, and software that must work on real hardware under operational constraints. ITAR (U.S. citizen/national, LPR, refugee, or asylee) is an apply-form gate, not a resume class-year knockout.

The resume leads with the full-stack spine and keeps real-time / systems / hardware-adjacent evidence prominent and deep — it does not collapse into a SpaceXAI ML internship narrative or a pure web resume.

## Team & Bar

The reviewer is screening a high-volume B-tier aerospace intern cohort before a HackerRank OA and a Med–Hard multi-round technical loop (~5–8% funnel; bottleneck: tech rounds). They reward evidence that the candidate ships software others depend on, debugs and optimizes under constraints, and can operate in a fast, ownership-heavy culture. Strong signals: JD languages demonstrated inside bullets (especially C++/Python); production-style delivery with clear ownership; debugging, performance, and unit-testing discipline; computer-architecture / networking fluency; metrics that size real outcomes (latency, throughput, failure recovery, scale); and credible adjacency to real-time or embedded-style systems without forcing aerospace domain claims the candidate does not have.

## Screen Criteria

- Demonstrates at least one JD language through use in bullets — C, C++, C#, Java, JavaScript, or Python — not only in the Skills line; C++ and Python depth reads especially well against the company stack.
- Shows general SWE delivery: APIs or services, data/storage, deployment or cloud, debugging/testing, and end-to-end ownership of something used by others.
- Keeps real-time / systems / hardware-adjacent / mission-critical evidence visible in the top half (the company-fit differentiator) without turning the page into a narrow embedded specialist or a pure ML resume.
- Uses impact metrics (latency, throughput, performance wins, failure recovery, scale, test coverage where real) rather than vanity counts or club-ops filler.
- Signals documentation/requirements/architecture awareness and collaborative ownership where the page can support it — without padding soft-skill prose.
- Anti-patterns: leading with LoRA / LangGraph / agentic product framing as if this were a SpaceXAI-only ML internship; skills-list keyword stuffing with no backing bullet; club membership without engineering depth; notebook ML without delivery; a resume that reads purely web with zero systems/real-time adjacency at an aerospace company.
