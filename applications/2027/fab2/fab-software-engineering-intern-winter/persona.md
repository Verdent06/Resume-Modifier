# Fab Software Engineering Intern - Winter at Fab2

## Role Summary

A paid, in-office winter intern on Fab2's Fab team (Austin or San Francisco). Term begins in January with a preferred 4–8 month commitment; software interns are paid hourly at an annualized $114,000–$131,000 plus housing stipend. The intern builds full-stack applications, tools, and infrastructure for a software-defined semiconductor fab: frontend + backend data-driven apps that run the fab, plus software that sequences and controls fabrication operations and analyzes process-development data. The JD surface is general SWE (TypeScript or Rust/Go, systems fundamentals, from-scratch projects, databases/visualization/pipelines). The company identity is Keller/Zeloof “fab fab” hardware — software that operates physical process equipment, not a consumer web intern seat. Philosophy: ship in days or weeks. A GitHub/portfolio of things actually built is required to apply.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** software-defined semiconductor fab / hardware-adjacent process-control + fab data systems
- **track_divergence:** true

Required qualifications test current-student CS/CE (or exceptional SWE skill), strong programming in Rust and Go **or TypeScript**, systems fundamentals (memory, performance, concurrency), non-trivial software built from scratch, and interest in databases, visualization, or data processing pipelines. That is a general SWE / full-stack screen (`recruiting.md` Part III §11; `resume.md` Part III §12): shipped frontend + backend, APIs, data systems, TypeScript-path delivery. They do not name ML training frameworks, ROS, Kubernetes, or Terraform as a floor, so the spine is not `ai-ml`, `robotics`, or `dev-ops`. The company-fit signal is software next to a fab: sequencing/control analog, real-time or concurrent systems, memory/performance discipline, and data pipelines that would exist in a process-control environment — without fabricating Rust, Go, firmware, RTL, KiCad, Protobuf, or CRDTs. Lead with the full-stack spine and keep systems / concurrency / memory-performance evidence prominent and deep.

## Screen Criteria

- Demonstrates the JD language path through use in bullets — TypeScript for this candidate — not Skills-list only. Rust and Go are alternate JD paths, not invitations to invent them.
- Shows shipped frontend + backend, data-driven applications: APIs, databases, visualization, and data processing pipelines so fab-ops tooling is an obvious routing, not a stretch.
- Keeps systems fundamentals visible in the top half: memory, performance, concurrency, real-time or control-adjacent discipline — framed as engineered software, never as invented fab-equipment firmware, RTL, or semiconductor-process internships.
- Uses impact metrics (latency, cost, failure recovery, throughput, scale, hours saved) rather than vanity counts.
- Non-trivial from-scratch software is obvious (personal, academic, or professional) and matches a public GitHub.
- Anti-patterns: claiming Rust, Go, Protobuf, CRDTs, KiCad, Blender, Figma-as-skill, Snowflake, or firmware the page cannot defend; a pure agentic/LLM product resume with no systems or application delivery; notebook ML; club-ops filler; burying concurrency/memory/performance below the fold at a software-defined fab; Skills-only TypeScript.
