# Intern, Software Engineer AI Agents (Winter 2027) at Bot Auto

Recruiter lens shared by the writer and grader. Abstract bar signals only — no candidate entry names, no include/omit table.

## Role Summary

A paid Winter 2027 onsite internship on Bot Auto's **AI Agents** team in Houston (Greenhouse **5429357008** / req **3012**; Houston Office). Comp unlisted (C-tier intern **$22–38/hr** band). The team explores, prototypes, and productionizes AI agent technologies to accelerate productivity, automate workflows, and enhance knowledge sharing — building agents for software development, fleet operations, and business processes.

Day-to-day is **applied agent/product AI**: LLM integrations with internal systems/tools/data; agent workflows (planning, tool usage, memory, multi-step reasoning); prompt engineering, evaluation, and model optimization; backend services and APIs for scalable agent deployment; cross-functional automation; benchmarking agent frameworks/models/tools. This is **not** the Intern Deep Learning Engineer sibling (MS/PhD perception / world-model), **not** an ML-research rotation, and **not** an autonomy-stack SWE intern (ROS/perception/controls).

Company identity (`company.md` / `companies.md`): L4 autonomous trucking TaaS — Houston fleet operator for 3PLs/shippers, not a robotaxi. The JD surface is agents; the memorable company-fit signal is applying those agents to operational / fleet-ops workflows.

## Screen Criteria

Pass signals:
- Shipped **AI agent systems** — multi-step orchestration, tool use, planning/memory, or consensus gates — not a thin LLM API wrapper and not Skills-only "LangChain/agents."
- **Python in bullets**, not Languages alone. TypeScript through use is honest extra; do not invent Go, Java, or Kubernetes.
- **Eval discipline:** benchmarks, metrics, faithfulness/accuracy lifts, adversarial test cases, or HITL analogs — the JD's evaluation / model-optimization line.
- **RAG / vector / embeddings** through use when present — preferred, not a hard gate if the agent spine is strong.
- **Backend services and APIs** for deploying or serving agent workflows (REST, workers/queues, containerized delivery). Docker/AWS through use maps to preferred cloud/containerization.
- **Operational-workflow framing:** agents applied to automation, productivity, or decision-making — the differentiator is fleet-ops/TaaS identity, shown as applying agents to real operational processes, not as ROS/perception.
- Metrics that size impact (speedup, accuracy/faithfulness, latency, hours saved), landed as the closer (`resume.md` §4).

Anti-patterns:
- Notebook ML / research-first hook (LoRA, `model.fit()`, publications) burying the agent/product spine (`recruiting.md` §13 research vs applied split).
- Perception / world-model / ROS framing this JD does not test — and inventing autonomy-stack experience the page cannot defend.
- Off-axis lead: hard real-time C++ audio DSP, deal-sourcing GTM without agent/backend substance, or club-ops.
- Agent/LLM/RAG keywords stuffed in Skills with no supporting system.
- Inventing Go, Java, Kubernetes, LangChain, AutoGen, TensorFlow, scikit-learn, Snowflake, Databricks, Copilot, Fusion, Tableau.
- Metric-free architecture bullets a 7-second Greenhouse screen cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
