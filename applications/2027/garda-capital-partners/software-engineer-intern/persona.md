# Software Engineer Intern at Garda Capital Partners

## Role Summary

Summer 2027 Software Engineer Intern on Garda's Research and Technology (R&T) team in New York. The intern aids new lines of business solutions in Python and SQL, supports senior staff designing and implementing complete front-office/risk systems, and provides support for in-house and third-party applications. JD surface is generalist enterprise SWE at a global hedge fund: CS/Eng/Math/Quant Finance enrollment, Python ecosystem plus one statically typed language, DS&A/OS fundamentals, OOP, high code standards, and the ability to use AI-assisted workflows without depending on them. Company identity is a $12B+ AUM fixed-income relative-value shop — R&T builds internal trading-adjacent software, not a consumer product and not a quant-research desk.

## Screen Criteria

- Python and SQL demonstrated in bullets — APIs, pipelines, or production services — not Skills-only. These are the floor languages.
- At least one statically typed language (C++ or TypeScript if actually shipped) with bullet evidence, not a Skills token. Inventing Java is worse than honest C++/TypeScript depth.
- Shipped software with ownership: complete solutions, support of real systems, measurable outcomes — matches "designing and implementing complete solutions" with senior staff.
- CS fundamentals visible (data structures, algorithms, operating systems, OOP) via coursework plus engineered projects that can be defended in an OA.
- Financial-markets or financial-data signal is a plus on a genuine engineering spine — particularly fixed income curiosity — not jargon padding. Prior trading-desk experience is explicitly a plus, not a requirement.
- AI-assisted development as a habit with the ability to write and debug unaided is a plus layered on the SWE bar — leading with LoRA / notebook-ML / agent pipelines as if this were an ML seat is an anti-pattern.
- Class standing and degree on page must match "pursuing BS/MS in CS, Engineering, Mathematics, or Quantitative Finance."

## Anti-Patterns

- Screening as AI/ML systems or research engineer because the JD mentions AI-assisted workflows.
- Python or SQL named in Skills with zero bullet evidence at a firm where both are the intern floor.
- A statically typed language in Skills only, with no work that would survive "walk me through this."
- Club-ops, community-growth, or CAD/mechanical filler with no software the role tests.
- Soft, metric-free shipping claims where enterprise R&T expects complete, supportable solutions.
- Finance-jargon padding (P&L, "prop desk," invented FI trading internship) without the engineering the req tests.
- Naming Snowflake, Databricks, Copilot, Fusion, or Tableau — not in inventory and not on this JD.
