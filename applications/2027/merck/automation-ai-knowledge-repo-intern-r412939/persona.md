## Role Summary

A paid Future Talent Program internship (up to 12 weeks; typical May/June start) onsite at **USA — Pennsylvania — West Point** (Workday req **R412939**; program codes FTP2027 / RL2027). Comp is the Workday FTE band **$39,108–$111,111** (intern hourly unpublished). Flexible Work Arrangements: **Not Applicable**.

The intern sits with Merck Research Labs **Robotics** and **Workflow Data Capture (WDC)** teams. Day-to-day is **applied AI on automation-script knowledge**: analyze existing automation scripts, GitHub repos, documentation, and historical troubleshooting records; develop and evaluate an **AI-enabled knowledge repository** that helps scientists and engineers understand scripts, debug, and follow standardized practices; write user guidance and present at the intern symposium. Cross-site partners: Boston and South San Francisco.

This is **not** the Business Intelligence Intern (**R412411**), not a bench-lab rotation, and not an ML-research paper. Surface requirements are Python + SQL toward scripts/APIs/lightweight apps, working C# or C/C++, Git/GitHub. Preferred: LLMs, RAG, knowledge graphs, vector databases; interest in laboratory automation / scientific software; technical documentation; debugging/quality.

Company identity (`company.md` / `companies.md`): Fortune-class pharma R&D lab-automation + scientific software. Domain (GMP-adjacent research labs, automation scripting) is flavor on an applied-AI knowledge-platform spine — not a second engineering track that requires ROS or wet-lab hours.

## Screen Criteria (abstract)

Pass signals:
- Hands-on LLMs / AI agents / retrieval: multi-step orchestration, embeddings, vector similarity, or a retrieve-then-generate pipeline — the JD's "AI-enabled knowledge repository" plus preferred RAG / vector databases / knowledge-graph concepts. Named through use beats a Skills-only claim.
- Evaluation / troubleshooting discipline: eval harnesses, held-out tests, faithfulness/accuracy lifts, or a diagnosed defect with a before/after — analog to "develop and evaluate" and to automation error tracking.
- Python and SQL demonstrated in bullets (scripts, APIs, lightweight applications, freshness/validation), not Skills alone. C++ (or C#) through use if listed — the JD's working-knowledge floor; do not invent C#.
- Data plumbing over messy records: ingest irregular sources, GitHub-shaped repos, documentation, or historical logs into something queryable — analog to analyzing automation scripts and records.
- Git / GitHub visible (header and/or CI/repo integration). Technical-documentation analog is a plus (user guidance, standardized practices) when it sits on real engineering, not club-ops writing.
- Cloud/container evidence (Docker/AWS) as supporting MLOps-lite, not a DevOps intern rewrite.
- Metrics that size impact (accuracy/faithfulness, latency, hours saved, throughput), landed as the closer (`resume.md` §4).
- Stats/technical coursework visible in Education is a plus for the scientific-discipline major line.

Anti-patterns:
- ML-research framing: publications, novel methods, notebook `model.fit()` with no retrieval, no pipeline, no delivery (`recruiting.md` §13 research vs applied split). This req is an applied knowledge platform for lab software.
- Robotics/ROS/controls lead, or claiming laboratory-automation internships, Hamilton/Tecan/Opentrons stacks, or Merck platforms the page cannot defend. Preferred is *interest*, not a fabricated bench rotation.
- Off-axis lead: pure frontend, pure audio-DSP hobby, or club-ops fronting an AI-knowledge intern req. C++ systems depth can support the required-language floor — it should not replace the RAG/agent spine.
- Agentic/LLM/RAG/vector claims only in Skills with no supporting system.
- Inventing Snowflake, Databricks, Copilot, Fusion, Tableau, C#, Kubernetes, TensorFlow, or knowledge-graph products not in inventory.
- Metric-free architecture bullets the recruiter cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
