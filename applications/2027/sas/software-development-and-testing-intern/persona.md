## Screen Criteria (abstract)

Pass signals:
- Shipped applications: frontend framework + backend/API + persistence or deploy, narrated decision-by-decision (`resume.md` §12). Keyword-through-use for Python, React, Angular, HTML/CSS, APIs, Docker, Git — not Skills alone (`resume.md` §2).
- Testing / quality analog: a diagnosed defect with a before/after, fault-tolerant recovery, or CI (pytest / GitHub Actions). The JD title is Development **and** Testing.
- Business-problem-with-code or analytics-adjacent delivery: a pipeline, ranking, or API that replaced a manual process — company-fit without inventing SAS procedures.
- Polyglot proof for languages the candidate actually has. JD or-list includes Java / C# / SAS / R / Go — **do not invent those**. Python / TypeScript / C++ / HTML/CSS / React / Angular through use beats a Skills-only claim.
- Cloud/container through use (AWS, Docker). Kubernetes / Jenkins / GCP / Azure are not fabrication targets.
- Metrics that size impact (error-rate, hours saved, latency, throughput), landed as the closer (`resume.md` §4).
- Class-year on the page: `Expected May 2028` — honest Junior / rising-junior standing for Summer 2027; not graduating before December 2027.

Anti-patterns:
- Skills-line Java / C# / SAS programming / R / Go / Jenkins / Kubernetes / Azure / GCP with zero bullet evidence (fabrication smell).
- Inventing those tools, or claiming a SAS / Viya / Base SAS internship the page cannot defend.
- Leading as an ML-research / LoRA / notebook `model.fit()` intern when the role tests product software + testing (`recruiting.md` §13 applied vs research split).
- Off-axis lead: hard-real-time C++/audio-DSP or club-ops fronting a product SWE/SDET intern at an analytics ISV.
- Metric-free architecture bullets the recruiter cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
