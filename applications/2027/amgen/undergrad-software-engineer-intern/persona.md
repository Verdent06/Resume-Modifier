## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names (**Python**, **SQL**). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). **Do not invent Java or Scala.**
- Shipped application software: develop / test / debug / deliver components — REST/APIs, a persistence decision, and a deploy path (cloud/web) tied to an outcome (`resume.md` §12).
- Business-process → programming logic: messy manual or spreadsheet workflows turned into maintainable software with a witness metric (hours saved, failure-rate drop, scale).
- Cross-functional / stakeholder delivery (internal or external customers) without claiming an Amgen, pharma, or ERP/CRM internship the page cannot defend.
- Impact metrics (latency, cost, hours saved, precision, scale), not vanity counts (`resume.md` §4).
- Class-year on the page: `Expected May 2028`; GPA 3.66 satisfies the 3.0 floor if they look.

**Anti-patterns:**

- Skills-line Java, Scala, Snowflake, Databricks, Copilot, Fusion, or Tableau with zero bullet evidence (fabrication smell). None of those are JD must-haves; absence is honest.
- Notebook ML / LoRA / agentic-product lead as if this were an ML-research or R&D intern seat because the parent is biotech.
- Hard-real-time C++/audio-DSP as the first-pass identity when the role tests application SWE (systems depth can support, not lead).
- Club-ops, community-growth, or coursework-only framing with no shipped application.
- Claiming Amgen, biotechnology lab, ERP, CRM, or Java/Scala production the page cannot defend.
- Thin single-bullet entries that dilute a full-stack + process-to-software spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
