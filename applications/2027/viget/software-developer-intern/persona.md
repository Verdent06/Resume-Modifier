## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names (**Python**; HTML/CSS). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). TypeScript/React/Angular as the JS-framework analog. **Do not invent Ruby, Rails, or Elixir.**
- Shipped web application software: REST/APIs, a persistence decision, and a deploy path (cloud/containers) tied to an outcome (`resume.md` §12). Flask/FastAPI is the honest Rails analog.
- Designer-adjacent UI kept visible in the lead window because of track divergence — interactive web surfaces, not a Figma-cert line.
- Client- or stakeholder-scoped work on that same spine — contracted delivery, non-engineer users, pairing/ownership without a large backend team.
- Testing/CI through use as a TDD analog (pytest, GitHub Actions) — not a coverage-percentage vanity metric (`resume.md` §4).
- Impact metrics (hours saved, failure-rate drop, qualification rate, scale), not vanity counts.
- Class-year on the page: `Expected May 2028`; GPA 3.7 is fine for a C-tier intern screen.

**Anti-patterns:**

- Skills-line Ruby, Rails, Elixir, Java, C#, Snowflake, Databricks, Copilot, Fusion, or Tableau with zero bullet evidence (fabrication smell). Absence of Rails is honest.
- Notebook ML / LoRA / agentic-product lead as if this were an AI intern because Viget publishes AI essays.
- Hard-real-time C++/audio-DSP as the first-pass identity when the role tests web apps with designers (systems depth can support, not lead).
- Club-ops, community-growth, or coursework-only framing with no shipped application.
- Claiming Viget clients, Rails production, or TDD-as-prior-job when the page cannot defend it.
- Thin single-bullet entries that dilute a full-stack + agency-delivery spine.
- Generic AI-written essays or an unrehearsed video — this shop screens those out on purpose.
