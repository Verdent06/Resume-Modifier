The intern writes clean, documented, tested code on an **active client engagement**; uses modern stacks and cloud (AWS, Azure, or GCP) plus DevOps tools; sits code review and pairing with Consultants; debugs, refactors, and documents existing systems; contributes to data models and integrations when the project needs it.

Company identity (`company.md` / `companies.md`) is **boutique technology consulting** — live client software in retail/distribution, financial services, healthcare, insurance — not a product-SWE shop and not Big Four. This is **not** Design Intern **7999446003** and **not** Client Services Intern **7999472003**. Do not invent Java, C#, Azure, GCP, or UDig client names.

## Track Decision

- **screen_track:** `full-stack`
- **differentiator:** boutique tech consulting / client-facing delivery (live engagements, pairing with Consultants)
- **track_divergence:** true

The posting's requirements literally test general intern SWE (`resume.md` Part III §12; `recruiting.md` Part III §11): object-oriented or modern language (**Java, C#, Python, or JavaScript/TypeScript**), data structures, algorithms, Git; REST / SQL / cloud as pluses; write/test/debug/document. That routes to `full-stack` — the default for a generic SWE intern req. Do **not** route `dev-ops` because DevOps tools and cloud appear as exposure, not an SRE bar. Do **not** route `ai-ml` because the firm also sells data/AI — this req is Software Engineering Intern.

UDig's dominant engineering identity is **client-delivery consulting**, distinct from generic product-SWE, so divergence is true: the resume leads with the `full-stack` spine **and** keeps stakeholder/client-scoped shipping prominent in the lead window. Do not lead as notebook ML, LoRA-research, or hard-real-time C++/audio-DSP.

## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names (**Python**, **TypeScript**). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). **Do not invent Java or C#.**
- Shipped application software on a delivery timeline: REST/APIs, a persistence decision, and a deploy path (cloud/containers) tied to an outcome (`resume.md` §12).
- Client- or stakeholder-scoped work kept visible in the lead window because of track divergence — contracted delivery, non-engineer users, pairing/ownership without a large backend team.
- Debug/refactor evidence with a before/after (failure rate, qualification rate, latency) — analog to "help debug, refactor, and document existing systems."
- SQL / REST / cloud through use as pluses; Git on Skills or through use is enough at intern exposure.
- Impact metrics (hours saved, failure-rate drop, precision, scale), not vanity counts (`resume.md` §4).
- Class-year on the page: `Expected May 2028`; GPA 3.66 is fine for a C-tier intern screen.

**Anti-patterns:**

- Skills-line Java, C#, Azure, GCP, Kubernetes, Snowflake, Databricks, Copilot, Fusion, or Tableau with zero bullet evidence (fabrication smell). None of those are exclusive must-haves; absence is honest.
- Notebook ML / LoRA / agentic-product lead as if this were an AI/Data Analytics intern because the firm also sells AI.
- Hard-real-time C++/audio-DSP as the first-pass identity when the role tests application SWE on a client team (systems depth can support, not lead).
- Club-ops, community-growth, or coursework-only framing with no shipped application.
- Claiming UDig, Java/.NET, Azure/GCP production, or a named Fortune 500 client the page cannot defend.
- Thin single-bullet entries that dilute a full-stack + client-delivery spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
