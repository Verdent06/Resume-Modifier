# Fullstack Engineering Internship, Product Team at Composio

## Role Summary

Fall 2026 / Winter 2027 Fullstack Engineering Internship on the Product Team — paid ($10k/mo), onsite San Francisco. The intern elevates developer ("Composio Platform") and consumer ("Composio For You") web experiences, ships elegant interfaces on the frontend and SDK, works with customers to improve the product, and writes crisp docs. JD surface is product full-stack (zero-to-one web + SDK, craft, writing). Company identity is agent-tool infrastructure: a unified API so AI agents talk to GitHub, Gmail, Notion, Salesforce, and 250+ tools — not an ML-training rotation.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** agent-tool infra / AI-native product (built with AND for LMs)
- **track_divergence:** true

Requirements literally test core product engineering: full-stack projects from scratch, frontend + SDK craft, customer-facing product work, and technical writing (`resume.md` Part III §12 / `recruiting.md` Part III §11). There is no training, inference-research, or data-pipeline bar, so the spine is not `ai-ml`. Bonus stack is TypeScript / React / Tailwind / Next.js — still a web product screen. The differentiator is the company's engineering identity: infrastructure at the agent–tool boundary, plus the JD's "ai native" bar (built *with* language models *and* built *for* them). The resume leads with a full-stack spine and keeps AI-native / agent-tool evidence prominent and deep — it does not flip the page into research ML or bury product-web shipping.

## Team & Bar

Composio is B-TIER (`companies.md`): Ashby ATS, human reads the PDF earlier than Workday OA-gated big-tech; no standard OA. Next filter is a practical tech pre-screen (not LeetCode; coding agents encouraged; firm-reported ~2% pass; ~240 interviews per hire). Bottleneck is resume + practical screen; estimated offer ~1–3%; tiny cohort. Recruiter voice: a product engineer who has shipped full-stack from zero, cares about craft, can hold many personas, writes clearly, and has actually used LMs as both a building block and a product surface. Strong signals: shipped systems with users; TypeScript/React demonstrated in bullets not Skills alone; agentic or LM-native product work that reads as engineered (orchestration, eval, tool-use) not a notebook; founder / large side-project / hackathon energy; quantified UX or delivery impact. Soft must-haves — posting says if you are very good, nothing is a must per se — still function as screen criteria, not knockouts.

## Screen Criteria

- Full-stack product shipping: web UI plus API or SDK, built from scratch / zero-to-one, with a real user or customer — not Skills-only frameworks (`resume.md` §12). Breadth across the stack plus depth in at least one layer.
- JD bonus languages in bullets, not Skills alone: TypeScript and React used inside an architectural decision. Do not invent Next.js or Tailwind.
- Differentiator visible in the top half: built *with* language models *and* built *for* them (agent orchestration, eval/quality gates, tool-calling, or an LM-backed product) — not a buried "AI" label and not a research-track pivot.
- Product craft / taste: an interface or SDK decision the reader can picture (frontend performance, dashboard, docs-quality explanation), not only backend ETL.
- Independent ownership plus customer or stakeholder contact (sole-engineer delivery, paying users, or scoped client work).
- Quantified impact (latency, cost, accuracy, throughput, revenue, scale) so "delightful experience" and "zero-to-one" claims can be sized.
- Anti-patterns: tutorial-grade projects; Skills-only TypeScript/React; notebook ML without delivery; invented Next.js/Tailwind; leading with an off-axis systems/DSP lane that buries product-web and AI-native signal; thin club-ops filler; metric-free ambitious claims.
