# Software Engineer Intern (Summer 2027) at Tower Research Capital

## Role Summary

Onsite New York SWE intern on Tower's engineering side of a proprietary quantitative trading firm: optimize systems with network and systems programming to minimize latency; design systems that collect, analyze, and visualize large data; build pipelines that capture reference and market data and serve them quickly; build algo-trading systems; and ship (AI-assisted) automation that makes trading operations more efficient. The JD surface is generic high-bar SWE — CS (or related) student, OOP, a language from the C++/Golang/Java/JavaScript/Python/Rust or-list, SQL and relational databases, working Linux, problem-solving and communication, interest in financial markets. Company identity is HFT/low-latency electronic-trading infrastructure (FPGA and hardware acceleration appear in the firm story; they are not intern-req filters and must not be faked). This is **not** Quant Trader, **not** Quant Developer, **not** Tower Research Ventures fullstack.

## Track Decision

- **screen_track:** full-stack (general SWE — the JD requirements literally test OOP, a language or-list, SQL/relational databases, Linux, and CS-student status)
- **differentiator:** low-latency / HFT trading-systems / market-data infra — systems programming to cut latency, market/reference-data pipelines with fast access, algo-trading systems, large-data collect/analyze/visualize
- **track_divergence:** true — generic-SWE requirements at an HFT/low-latency firm whose engineering identity is trading-systems and market-data infrastructure, not a product-SWE or CRUD shop. Spine stays `full-stack` (`reference/recruiting.md` III §11, `reference/resume.md` III §12). Differentiator-aligned systems, latency, and data-pipeline evidence stay prominent and deep. The page does not become a quant-research, FPGA, or trading-desk resume.

The spine is general SWE: ship real, defensible software; strong DS&A for a Med–Hard OA (CS MCQ + SQL + coding); JD languages the candidate can actually interview in, proven in bullets. The differentiator is carried by whatever on-page work demonstrates high-performance systems (concurrency, memory discipline, latency/throughput, correctness under load) and data ingestion / fast-access pipelines — kept in the first-read window, not buried.

## Team & Bar

Tower is S-tier quant/HFT (`reference/companies.md`) — HRT / Virtu / IMC peer band, Greenhouse resume → OA (~90 min CS MCQ + SQL + 2 coding; HackerRank **[directional]**) → 1–2 tech (DSA + probability) → behavioral, bottleneck OA + tech, <1–2% intern acceptance **[directional]**. Comp is $3,500–$4,200/week anticipated base plus housing and meals (JD). The screener is an engineer/recruiter at a firm that treats programming excellence, systems discipline, and SQL literacy as floors. What wins the human screen: C++ and Python proven in real systems work, not Skills-only; SQL in bullets, not Skills alone; high-performance or pipeline depth (latency, concurrency, memory, fast data access); honest language depth (do not invent Golang, Java, Rust, or FPGA); shipped, defensible projects a candidate can walk decision-by-decision; markets curiosity without fake desk experience. Class-year on page must show a current student in CS or related (Expected May 2028 qualifies; no class-year knockout on the posting).

## Screen Criteria

- At least one JD language from the or-list demonstrated in **bullets**, not Skills alone. C++ and Python are the honest floor when those are the languages the candidate can interview in; listing Golang, Java, or Rust without bullet proof is worse than omitting them.
- SQL and relational databases proven in bullets — the OA includes SQL and the qualifications list names both. Skills-only SQL fails this screen.
- High-performance / low-latency **systems** depth on the page: real-time constraints, concurrency, lock-free or memory-discipline, latency/throughput, production correctness — the HFT-adjacent signal that separates this firm from a generic SWE screen.
- Data-pipeline / fast-access evidence: ingest, normalize, store, and serve large data quickly — maps to market/reference-data pipelines and “fast and easy access.”
- End-to-end ownership and production impact with metrics (latency, throughput, %, scale) — soft, metric-free claims read thin at this bar.
- OOP and CS fundamentals visible (coursework + engineered systems) for a Med–Hard OA and a DSA/OOP tech loop.
- Markets interest without finance-jargon padding: stats/econ coursework or rigorously evaluated data systems are enough; prior trading-desk experience is not required.
- Class-year on page shows a current Bachelor's/Master's/PhD student in CS or related (Expected May 2028 is in window).

## Anti-Patterns

- Re-targeting to an ML-research / LoRA / agent-pipeline lead as if this were a quant-research or ML internship — the req is general SWE; (AI-assisted) automation is a supporting responsibility, not the spine.
- All-CRUD / all-web-app page with no systems-performance or pipeline/fast-access signal — reads generic at a firm whose identity is latency and market-data infra.
- Golang, Java, or Rust named in Skills with zero bullet evidence.
- C++ or Python named in Skills with zero bullet evidence.
- SQL named in Skills with zero bullet evidence.
- Invented FPGA, hardware-acceleration, or trading-desk internships — the firm story names FPGA; the intern JD does not require it, and faking it is an emergency.
- Soft, metric-free shipping claims where correctness, scale, and performance are the firm's selling point.
- Thin single-bullet filler that dilutes a strong systems + pipeline spine.
- Club-ops or community-growth framing with no engineering the role tests.
