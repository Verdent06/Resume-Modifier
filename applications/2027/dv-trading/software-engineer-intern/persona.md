# Software Engineer Intern at DV Trading

## Role Summary

SE Intern building low-latency applications and trading tools inside DV Trading's large production codebase, collaborating with developer and trading teams in NYC (onsite 5 days/week). JD surface is generalist trading-tech SWE: C++ and/or Python proficiency, navigating existing codebases, strong quantitative/analytical skills for performance-sensitive problems, and effective use of AI coding tools while owning and reviewing generated code. That AI language is developer-tooling fluency — ship faster with assistants, review everything — not an ML-systems internship. Company identity is prop-trading / market-making infrastructure: low-latency production systems where performance and correctness matter at scale.

## Track Decision

- **screen_track:** full-stack (general SWE)
- **differentiator:** trading-tech / low-latency production systems (C++/systems depth) + AI-assisted development as daily engineer habit (NOT ai-ml track)
- **track_divergence:** false

The screen spine is general SWE per `recruiting.md` Part III §11 and `resume.md` Part III §12 — ship working software, DS&A foundation, C++ and Python proven in bullets. The differentiator is flavor on that spine (production trading tools, latency/performance culture, large shared codebase discipline), not a second track. Do not pivot the resume to ai-ml research, LoRA fine-tuning, or agentic-product lead framing because the JD mentions AI coding tools.

## Team & Bar

DV Trading is unrated in `companies.md` but sits in the quant/prop-trading peer set (funnel family near IMC, HRT — OA-gated, C++/Python heavy, low-single-digit acceptance, brutal-early cycle per `recruiting.md` Part I §1 and Part II §8). Recruiter voice: interns who already demonstrate CS fundamentals, ship in production codebases, communicate with trading and engineering stakeholders, and show performance-sensitive engineering depth. Comp is $50/hr paid — selective but below top-tier quant headline rates; bar still expects language depth and systems signal. Eligibility window Winter 2027–Summer 2028 is a hard gate on the page.

## Screen Criteria

- C++ and/or Python proven in bullets — not Skills-only. Both in evidence is ideal when honest; inventing languages absent from work is worse than deep Python + C++.
- Low-latency, real-time, or performance-engineering depth that reads as trading-tech adjacent (concurrency, hot loops, zero-allocation constraints, sub-millisecond client-side wins).
- Production codebase / shipped-tools signal: REST APIs, deployed services, release-ready binaries, measurable reliability or cost outcomes.
- DS&A / OOP foundation visible via coursework and engineered projects defensible in a coding interview.
- Quantitative or analytical framing where numbers size impact — prop firms read performance-sensitive problem solving.
- AI-assisted development as **habit with review and ownership** is a plus layered on the SWE bar — absence is not automatic reject; leading with ML research pipelines as if this were an ai-ml internship is an anti-pattern.
- Class-year on page must fall in Winter 2027–Summer 2028 (Expected May 2028 is in window).

## Anti-Patterns

- Screening as AI/ML systems engineer because the JD mentions AI coding tools.
- C++ or Python named in Skills with zero bullet evidence at a firm where language is a floor signal.
- Club-ops or community-growth framing with no engineering depth.
- Soft, metric-free shipping claims where production impact is the firm's selling point.
- Thin single-bullet filler diluting a strong production + systems spine.
- Finance-jargon padding without engineering substance.
