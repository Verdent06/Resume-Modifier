## Screen Criteria

**Pass signals (abstract — the writer discovers which entries carry them):**
- Python and SQL demonstrated through use in bullets, not only the Skills line (`resume.md` keyword-through-use).
- End-to-end data or ML workflow: ingest/integrate messy or diverse data → transform/pipeline or feature work → model, scoring, or insight → measured outcome. Preprocessing through evaluation beats `model.fit()` (`resume.md` §14; `recruiting.md` §13).
- Experiments or business-tied metrics (accuracy, precision, hours saved, throughput, cost, KPI-style lifts) as the closer (`resume.md` DRAW/AR).
- Production-shaped delivery: APIs, cloud (AWS), pipelines, dashboards, or stakeholder-facing data products — analog to "platforms and pipelines" and "insights for clients/customers."
- Prompt/LLM or applied-ML evidence when it is a real system (eval, deployment, data integration), not a buzzword.
- Fintech-backend / enterprise-delivery signal kept visible in the lead window because of track divergence: shipped systems in a business/financial context, not hobby ML.
- Quantitative coursework (stats, calc, econ) visible in Education as math-foundation signal.

**Anti-patterns:**
- Generic SWE / full-stack product resume that never shows data pipelines, SQL, or ML workflow — wrong program.
- Notebook ML or `model.fit()` with no delivery, no pipeline, no measured outcome.
- Skills-only Python/SQL/AWS/LLM with no bullet proof.
- Invented Snowflake/Databricks/Tableau/Fusion/Copilot claims (JD names them; absence in bullets is honest; stuffing them is a fabrication smell).
- Club-ops or community-growth filler occupying prime slots.
- Pure audio-DSP / embedded systems as the lead with no data/AI analog.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact.
- Treating this as Code for Good / SWE Program (HackerRank-first, secure-coding SDLC) — different req.
- Invented messy-dataset bullets or fabricated metrics not grounded in the candidate's actual work.
