# Software Engineering Internship — San Francisco (Summer 2027) at Samsara

## Role Summary

A Summer 2027, full-time paid, hybrid (3 days/week SF) software internship on Samsara's Connected Operations Cloud. Interns are matched across a range of engineering teams: backend infrastructure that scales IoT data ingestion and storage across 15,000+ hardware asset types and tens of thousands of customers; full-stack work turning that data into actionable insights alongside product and design; React Native mobile infrastructure; and embedded software on Samsara hardware (edge AI, multimedia frameworks, power management, real-time data processing). The JD surface is a broad, general SWE req — enrolled junior on track to graduate Spring/Summer/Fall 2028 or Winter 2029, curiosity/self-drive, ownership end to end — with a named stack (Golang, TypeScript/React, GraphQL, React Native) where direct experience is not required but similar technology is strongly encouraged. Samsara's company identity is real-time IoT data at scale — a mission-critical system of action spanning cloud, mobile, and embedded/edge, where engineers build for scale and even visit customers in person.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** IoT / build-for-scale data platform + real-time / embedded / multimedia edge systems
- **track_divergence:** true

The literal screen tests general SWE / full-stack fundamentals and the ability to ship end to end across web, backend, and data — not ML research, ROS, or SRE/infra specialization — so the resume spine is full-stack/general SWE with real backend and data-pipeline depth. Samsara's memorable company-fit signal is software built for scale next to real-time and embedded/edge systems (IoT data ingestion at scale on one axis; multimedia/real-time processing on hardware on the other). The resume leads with the full-stack spine (shipped products defensible layer-by-layer, React/TypeScript web, backend services, data pipelines built for scale) and keeps real-time / systems / embedded-adjacent evidence prominent and deep in the top half — it does not collapse into a pure web resume or a narrow embedded/DSP specialist page, and it does not lead with agentic-AI/LLM product framing as if this were an ML internship.

## Team & Bar

The reviewer is screening a selective, rolling A-tier-profile intern cohort ahead of a CoderPad/Codility OA (4–5 timed LeetCode-style DSA questions) and a live technical coding round plus a customer-obsession behavioral round. Everyone gets the OA, so the resume's job is to win the team-match and the interview, not clear a knockout. Signals that win here: JD/adjacent languages demonstrated inside bullets (TypeScript especially, plus backend and systems languages), not just in the Skills line; genuinely engineered, shipped products with clear end-to-end ownership the candidate can defend at every layer; evidence of building for scale (data ingestion/storage/throughput, pipelines, concurrency); React/TypeScript web depth; and credible real-time / embedded / multimedia adjacency that maps to Samsara's hardware/edge side without forcing IoT domain claims the candidate does not have. Impact metrics that size real outcomes (latency, throughput, failure recovery, cost, scale) beat vanity counts or club-ops filler. Curiosity/self-drive (side projects, hackathons) and ownership are explicitly rewarded.

## Screen Criteria

- Demonstrates at least one JD/adjacent language through use in bullets — TypeScript, plus a backend/systems language (Go-adjacent backend, Python, C++) — not only in the Skills line.
- Shows full-stack delivery: a web/UI layer, backend services/APIs, a database, and deployment/cloud, with at least one product defensible end to end (why this DB, why this API shape, what broke and how it was fixed).
- Shows building for scale — data ingestion/aggregation pipelines, storage, throughput, concurrency, or cost/latency wins — mapping to Samsara's data-platform identity.
- Keeps real-time / embedded / multimedia / systems evidence visible in the top half (the company-fit differentiator) without turning the page into a narrow specialist or burying it at the bottom.
- Uses impact metrics (latency, throughput, failure recovery, cost reduction, scale) rather than vanity counts; roughly one metric per two bullets.
- Anti-patterns: leading with LoRA / LangGraph / agentic-AI product framing as if this were an ML internship; skills-list keyword stuffing with no backing bullet; club membership without engineering depth; notebook ML without delivery; a resume that reads purely frontend/web with zero backend, data-at-scale, or systems adjacency at an IoT data-platform company.
