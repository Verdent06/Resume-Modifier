# Software Engineer Intern (Winter 2027) at Figma

## Role Summary

Winter 2027 Software Engineer Intern at Figma (NYSE: FIG), San Francisco or New York Hub, January 4, 2027 start, $55/hr plus housing stipend and travel reimbursement. Interns embed on a small engineering team and ship a project by the end of term — user-facing product, platform/infrastructure, or security, matched from the applicant's stated interests. JD surface is generic SWE intern: clean code in at least one general-purpose language (C++, JavaScript, Python, Java as examples), DS&A, school/work/personal problem-solving, AI-assisted development tools as a usage example, curiosity from infrastructure to UI, collaboration and feedback. Company identity is a real-time collaborative design platform (multiplayer canvas: Design, FigJam, Dev Mode) — not generic CRUD and not an ML-research lab.

- **screen_track:** full-stack (generic SWE intern: ship features/tests/infra on an embedded team; at least one GP language; DS&A; `resume.md` Part III §12 / `recruiting.md` Part III §11)

- **track_divergence:** true

The literal requirements test general SWE / full-stack fundamentals — not a CRDT/multiplayer filter, not an SRE filter, and not a security-engineering filter. Spine is a shippable full-stack product (frontend or client, API, data, deploy) narrated decision-by-decision. Differentiator stays prominent and deep: real-time or user-facing product engineering (client performance, collaborative workflows, systems other people actually use). Do not collapse into a GTM/quant page, a notebook-ML / Copilot-as-skill page, or a DSP-only systems page. Do not invent JavaScript (TypeScript ≠ JavaScript), Java, Copilot, or security-lane work.

## Team & Bar

Figma is A-tier in `companies.md` (Very low acceptance; bottleneck = Byteboard reading crunch). Funnel: Greenhouse resume + essays → recruiter screen → Byteboard (~90 min: design-doc reading then implement) → hiring-manager project deep-dive → virtual onsite (applied coding, light architecture, behavioral). Recruiter voice: an intern who already ships clean, collaborative product work, can name a first-choice engineering area honestly, and will survive a timed reading + implementation assessment. Strong signals: shipped systems with metrics; polyglot depth in bullets not Skills alone; real-time or user-facing product evidence in the top half; AI-tool *usage* is a plus when tied to writing/debugging/optimizing code — not a Skills-line Copilot claim. Behavioral is a filter (`recruiting.md` §6). Grow-as-you-go: imperfect alignment is not a knockout. Cameras on; in-person onboarding.

## Screen Criteria

- Full-stack shipping with APIs, a client or UI, and a deploy path demonstrated in bullets — not Skills-only (`resume.md` §12). Breadth across the stack plus depth in at least one layer.
- Real-time or user-facing product engineering visible in the top half — the collaborative-canvas differentiator — without turning the page into DSP-only or infra-only.
- JD languages the candidate actually has (C++, Python) used inside architectural decisions, not asserted on a Skills line. Do not invent JavaScript or Java.
- Prior titled internship / co-op / production delivery visible — the JD asks for school, work, or personal technical problem-solving; titled shipping outranks club-ops.
- Debug / reliability / client-performance stories with before-after numbers (failure rate, latency, cost, FPS) — maps to "build, document, and maintain tests, features, or infrastructure" and "from infrastructure to UI."
- AI-assisted development as *usage in the work* (write/debug/optimize) is a JD nice-to-have; do not put Copilot on the resume. Claude/ChatGPT-class tools belong only if the pool already carries them.
- Class-year on page: `Expected May 2028` plus a January 2027 start is junior-year winter with return to school. JD has no class-year filter.
- Collaboration signal: stakeholder or cross-functional delivery, code-review-shaped engineering, not lone-wolf GTM scoring as the lead story.

## Anti-Patterns

- GitHub Copilot, Snowflake, Databricks, Fusion, or Tableau on the page — none are candidate inventory; Copilot is a JD *example* of AI tools, not a skill to claim.
- Invented JavaScript (TypeScript is not JavaScript) or Java to match JD language examples.
- Security-engineering framing with no security-lane evidence.
- Leading with GTM/quant deal-sourcing or low-level audio DSP when the req is product/collaboration shipping.
- AI-tool-only claims (prompting, Copilot) with no shipped product or debug story.
- Club-ops or thin single-bullet filler that dilutes a full-stack + real-time product spine.
- Languages or frameworks listed in Skills with zero bullet evidence.
