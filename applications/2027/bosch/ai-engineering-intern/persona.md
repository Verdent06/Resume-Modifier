## Screen Criteria (abstract)

Pass signals:
- Hands-on generative AI, LLMs, AI agents, or agentic workflows (multi-step orchestration, tool/API integration, structured output or eval) — not a thin chatbot wrapper or a notebook demo.
- Retrieval / vector / RAG analog: embeddings, vector similarity search, or a retrieve-then-generate pipeline — the JD's RAG / vector-database / knowledge-assistant plus.
- Evaluation discipline: eval harnesses, held-out tests, faithfulness/accuracy lifts, or explicit "evaluate accuracy, reliability, and limitations of AI-generated outputs."
- Python demonstrated through use in bullets, not Skills alone. APIs, automation, or software integrations in the same narrative.
- Data plumbing: aggregate/structure/store/expose data for analysis — analog to the JD's data-accessibility line.
- Differentiator visible near the lead: C++ or on-device/real-time/embedded-adjacent systems in bullets (not Skills-only), so the automotive-plus does not look bolted on.
- Metrics that size impact (accuracy/faithfulness, latency, cost, hours saved, throughput), landed as the closer (`resume.md` §4).
- Live GitHub on an intern engineering resume (`resume.md` §3). GPA ≥ 3.0 visible.

Anti-patterns:
- ML-research framing: publications, novel methods, notebook `model.fit()` with no agent, no pipeline, no delivery (`recruiting.md` §13 research vs applied split).
- Off-axis lead: pure frontend, PE-only GTM, or club-ops fronting an AI-for-engineering intern req.
- Agentic/LLM/RAG claims only in Skills with no supporting system.
- Inventing MATLAB/Simulink, AUTOSAR, ISO 26262, Snowflake, Databricks, Tableau, Copilot, Fusion, or Bosch/VM platform experience.
- Claiming brake/steer/embedded-control internships the page cannot defend.

- Metric-free architecture bullets the recruiter cannot size.
- Treating this as the Bosch Ventures / RBVC intern.
