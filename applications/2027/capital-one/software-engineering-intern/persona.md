# Software Engineer — Technology Internship Program (Summer 2027) at Capital One

## Role Summary

A 10-week, hybrid, rotational Software Engineer internship inside a large-scale "bank built as a technology company." The JD describes a "You Build It, You Own It" full-stack environment: customer-facing web/mobile apps on modern open-source frameworks, highly-available RESTful services, and Java-based backend systems at Big Data scale, running on Kubernetes/Docker/AWS with Terraform and Jenkins in the delivery chain. Basic qualifications are eligibility-only (degree timeline, continuing enrollment); the preferred list is broad general-SWE polyglot fluency (Java, Python, Go, Kotlin, C#, C/C++, SQL, JS) plus, distinctively, hands-on use of AI coding tools "beyond basic code completion." No ML/data-science specialization is requested anywhere in the JD.

## Track Decision

- **screen_track:** full-stack (general SWE)
- **differentiator:** breadth across the stack with real backend/persistence ownership, plus visible fluency with AI-assisted development tooling
- **track_divergence:** false

The screen spine is squarely general SWE/full-stack per `recruiting.md` §11 — the JD tests CS fundamentals and end-to-end shipping, not a specialized field. No pivot is needed; this is the same track the base resume (`applications/resumes/full-stack/full-stack-track.tex`) was already built for. The one JD-specific wrinkle is the explicit, repeated call-out of "AI-powered development tools" / "interactive AI tooling to accelerate productivity" as a preferred qualification — a differentiator layered on top of the standard full-stack bar, not a replacement for it.

## Team & Bar

Capital One's tech internship program is large-scale and rotational — closer to a big-tech-style pipeline than a startup's. Per `companies.md`, the screen is **school-blind** with the real bottleneck at the **OA** (CodeSignal, ~8–12% overall conversion), consistent with `recruiting.md` §1's framing that at this scale the OA — not resume polish — is the binding gate. The resume's job is to clear the human/ATS screen cleanly and support team-match after the OA, not to win on prestige. The bar: demonstrated full-stack ownership (frontend + backend + API + data + deploy), a real database/persistence decision, cloud/CI-CD delivery tied to shipped work, and — as a plus, not a floor — some evidence of using AI tooling as part of the engineering workflow rather than just naming it.

## Screen Criteria

- A frontend framework proven in real product work (React/Angular/Vue equivalent), not just listed in Skills.
- A backend service or API shown running in a real system, not a localhost demo.
- A relational or NoSQL database used inside an actual system decision (schema, query pattern, persistence trade-off).
- Cloud/deployment and CI/CD fluency (AWS, Docker, Kubernetes-adjacent, Jenkins/GitHub Actions) tied to something actually shipped.
- Java specifically present with real usage — it is the JD's named backend language and appears twice in the stack list.
- Trade-off fluency: a bullet defends a decision (why this DB, why this queue, why this protocol), not just names a tool.
- AI-assisted development tooling used with a concrete outcome (what it accelerated or improved), if present — a differentiator, but its absence is not itself a hard gate given it's a preferred, not basic, qualification.
- GitHub or an equivalent live link as proof of work on the flagship project/experience.

## Anti-Patterns

- A resume with backend/data signal but zero frontend or client-surface evidence, or the reverse.
- Skills-line name-dropping (Kubernetes, Terraform, NoSQL) with no bullet or tech-stack-line support.
- Java listed only in Skills with no entry actually built in it — a floor signal for this JD specifically.
- Vague cloud claims ("familiar with AWS") with no tied delivery.
- Vanity metrics standing in for real impact (uptime %, test-coverage %, LOC).
