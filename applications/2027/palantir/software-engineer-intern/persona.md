# 2027 Software Engineer, Internship at Palantir Technologies

## Role Summary

A paid, on-site Product Development (Dev / SWE) internship in Palo Alto, CA. The intern writes code into Palantir products (Gotham, Foundry, Apollo) on a small PD team — e.g. a Foundry front-end app or Gotham release infrastructure — through the full product lifecycle with a mentor, collaborating with PMs, designers, PREs, and business-development roles (FDEs / Deployment Strategists). Customer-site tours are possible; the job is still platform engineering, not a Forward Deployed intern seat. JD surface is generic SWE: CS/Math/SWE/Physics background; familiarity with data structures, storage systems, cloud infrastructure, and front-end frameworks; coding in Java, C++, Python, JavaScript, or similar. Company identity is defense/gov plus operational data platforms — mission-critical software used by many customers — so the memorable signal is shipped production systems and data/ops discipline, not consumer CRUD and not Palantir-product usage.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** defense/gov + operational data platforms
- **track_divergence:** true

The resume leads with a full-stack spine and keeps differentiator-aligned evidence prominent and deep — production shipping, data pipelines, client-facing delivery, real-time/systems discipline — without flipping into an FDSE-only or defense-specialist page. JD: languages at join do not matter; learn quickly. Java/Go/Spark/Cassandra on the company's stack are not a screen filter if absent.

## Team & Bar

The reviewer is an A-tier Lever screener before Karat and a Decomposition-heavy loop whose intern bottleneck is the **recruiter screen** (`companies.md`: 4 rds · Easy–Med · Karat · decomp · <2–3%). Recruiter voice: can this intern own a slice of a multi-customer platform, write code other teams and operators depend on, and communicate with engineers plus non-technical partners (Ownership, Collaboration, Trust)? Strong signals: production-style APIs or services with a deploy path; ETL / data-correctness / entity-resolution-shaped work; frontend frameworks through use; C++ or systems discipline so the page is not generic web; stakeholder delivery without reading as "only wants FDSE." Prestige is a tiebreaker, not a gate (`recruiting.md` §8). Clearance eligibility is valued, not a resume line. Class-year gate: graduating 2028, final internship before graduating — `Expected May 2028` on the page.

## Screen Criteria

- JD-family languages demonstrated in bullets, not Skills alone — C++, Python, and/or JavaScript/TypeScript through use. Java and Go are what the company ships today; absence in bullets is **not** a knockout (JD: learn at join). Inventing them is an emergency.
- Broad SWE fundamentals on the page: APIs or services, storage/data, cloud or deployment, and some frontend/client work (`resume.md` §12 keywords-through-use). React is named; frontend evidence should be real use, not a Skills-only React token.
- Production or production-shaped shipping: code that other people used, with a deploy path (cloud, containers, CI) so "contribute to Gotham/Foundry/Apollo" is believable without claiming those products.
- Differentiator visible in the top half: operational data (pipelines, aggregation, entity/record correctness, APIs over messy real-world datasets) and/or mission-critical systems discipline (real-time constraints, fault-tolerant recovery, ownership of a defect with a before/after) — not a consumer-SaaS page with zero data or systems signal.
- Ownership and collaboration via shipped systems, stakeholder or cross-functional delivery, and quality/debug stories — maps to JD principles without turning the resume into a consulting-only narrative.
- Impact metrics a recruiter can size in 30 seconds (latency, failure recovery, volume, hours saved, precision) — Palantir's intern work is features operators use.
- Class-year on page: `Expected May 2028` satisfies graduating 2028 / final internship Summer 2027.

## Anti-Patterns

- Claiming Palantir product experience (Gotham, Foundry, Apollo, AIP) or inventing Java, Go, Spark, Cassandra, Elasticsearch, Gradle, or a clearance in hand.
- Leading with notebook ML / LoRA / agentic-demo framing as if this were an ML-training internship.
- FDSE-only packaging: client-site delivery with no platform, API, or systems engineering the PD SWE intern job tests.
- Club-ops, GTM/quant sourcing, or deal-flow work with no engineering the role tests.
- Skills-only polyglot stuffing (especially Java/Go listed without inventory or bullets).
- Thin single-bullet filler that dilutes a production + data + systems spine.
- Tutorial-grade projects; metric-free architecture claims the candidate cannot defend in a project deep-dive or Decomposition follow-up.
