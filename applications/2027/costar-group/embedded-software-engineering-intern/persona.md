## Screen Criteria

**Pass signals (abstract):**

- Python and/or C++ demonstrated through use in bullets, not Skills alone. MATLAB is preferred-or, not a license to invent it.
- Applied ML / stats / data-analysis workflow: messy source → clean/aggregate or model with eval → tool, pipeline, or documented finding. Preprocessing through evaluation beats `model.fit()` (`resume.md` §14).
- Comfort with imperfect data visible as a real defect, irregular export, or quality gate — not a clean tutorial dataset only.
- Differentiator visible in the lead window: real-time constraints, C++ systems, signal/DSP-adjacent, or on-device inference — without turning the page into a DSP-hobby-only document or a fake embedded-firmware internship.
- Preferred extras (PyTorch, OpenCV, CV, sensor fusion, robotics, hardware lab) only through real use. Skills-only PyTorch/OpenCV is a ding; invented camera/LiDAR internships are an emergency.
- APIs/REST as supporting campus-program preferred, not the spine.
- Class-year on the page: `Expected May 2028`. GPA 3.66 clears the 3.0 floor (`resume.md` I.3).

**Anti-patterns:**

- Generic Technology Intern / marketplace SWE resume (React/Java/C#/.NET) that never shows ML, analysis pipelines, or C++ signal work — wrong twin.
- Firmware / MCU / oscilloscope / PCBA / OpenCV / MATLAB / TensorFlow / ROS invented or Skills-stuffed.
- Notebook ML without delivery, or LoRA-as-the-only-story with no pipeline or imperfect-data analog.
- PE / search-fund / GTM lead that buries sensor-ML and C++.
- Club-ops filler; vanity metrics; two pages; Skills-only polyglot.
- Treating this as an OA-first FAANG SWE intern or as a Vision & Learning research intern.
