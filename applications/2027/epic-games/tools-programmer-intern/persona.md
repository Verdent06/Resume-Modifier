## Screen Criteria

**Pass signals (abstract):**

- **C++ demonstrated in bullets**, not Skills alone. Greenhouse asks whether C++ appears on the resume as school/work/personal projects — Skills-only fails that knockout (`resume.md` §2 keyword-through-use).
- Tools / systems / toolchain ownership: shipped C++ systems, pipeline or editor-adjacent tooling, or workflow automation with a witness metric — the Content Architecture signal without inventing Unreal.
- OOP, patterns, algorithms, and data structures visible in work (class modeling, ownership, concurrency/memory discipline), not only coursework.
- Debugging and defect/workflow resolution through use — the intern's stated day-to-day.
- Windows or native/desktop toolchain adjacency as flavor; packaging, distribution, streaming, or binary/build-adjacent work as company-fit on the spine.
- CS fundamentals defensible in a Medium coding/tech round (`recruiting.md` §6 DS&A; Epic bottleneck is tech rounds).
- Class-year on the page: `Expected May 2028` (current student; Junior at a 2027 intern). GPA 3.66 is a plus (`resume.md` I.3); this JD prints no GPA floor.

**Anti-patterns:**

- **Frontend-heavy lead** (visualizer UI, React/Angular dashboard as the first-pass story) — this is Content Architecture C++ tools, not the frontend intern req.
- C++ named in Skills with zero bullet evidence — fails the Greenhouse C++-on-resume knockout and reads as stuffing.
- Invented Unreal Engine, C#, Perforce, Slate, Blueprints, or editor plugins the page cannot defend.
- Treating this req as Build Operations Tools (C# / GUI / CI telemetry) or as a generic web intern.
- Club-ops, community-growth, or coursework-only framing with no systems the role tests.
- Soft, metric-free shipping claims where engine tools care about correctness, performance, and workflow defects (`resume.md` §4).
- Thin single-bullet entries that dilute a C++ tools/systems spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact.
