## Screen Criteria

**Pass signals (abstract):**

- HTML and SQL through use in architectural decisions (web UI, REST/APIs, persistence, query/validation) — not Skills-only (`resume.md` §2, §12). TypeScript covers the JD's ".NET/TypeScript is a plus" honestly.
- Shipped full-stack software other people used: APIs, databases, dashboards/navigation, stakeholder handoff — maps to internal apps that operations employees actually run.
- Debug / test / support analog: failure recovery, MIME/auth/upload bugs, qualification-rate lifts — not "we tested it" with no number.
- UX / navigation / performance evidence somewhere (front-end, visualizer, latency) — JD names user experience, navigation, and system performance.
- CS fundamentals visible: DS&A coursework plus engineered work defensible in an Easy live walkthrough if invited.
- Class-year and GPA on the page: `Expected May 2028` plus 3.66 clears preferred 2.7 and returning-student eligibility.
- GitHub on the page (`resume.md` §3).

**Anti-patterns:**

- Invented **C#, Blazor, .NET, Microsoft Azure** — not in honest inventory; fabrication smell at a C#/.NET shop.
- Invented **Snowflake, Databricks, Copilot, Fusion, Tableau, or Sentry** — banned.
- Skills-only HTML/SQL/TypeScript with zero bullet evidence.
- Hard-real-time C++/audio-DSP as the first-pass identity when the role tests web/SQL/internal-apps SWE.
- Notebook ML or `model.fit()` as the identity; mill DCS/PLC/process-control framing this intern does not do.
- Club-ops filler; metric-free architecture bullets the recruiter cannot size (`resume.md` §4).
- Thin single-bullet entries that dilute a full-stack internal-tools spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact.
