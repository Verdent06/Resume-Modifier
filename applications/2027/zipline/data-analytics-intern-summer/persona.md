**Pass signals (abstract — the writer discovers which entries carry them):**
- Python and SQL demonstrated through use in bullets, not only the Skills line (`resume.md` keyword-through-use). PostgreSQL/SQL through use is the honest analog; do not invent Mode, Sigma, Snowflake, or Databricks.
- End-to-end applied-analytics workflow: messy or multi-source operational data → gather/merge/aggregate → EDA/transform → score, KPI, ranking, or recommendation → visualization or stakeholder report → measured outcome. Preprocessing through evaluation beats `model.fit()` (`resume.md` §14).
- Stakeholder-facing operational-analytics signal kept visible in the lead window because of track divergence: shipped analysis for a production / inventory / quality / ops analog (floor or leadership customer), not hobby ML and not consumer-app feature work.
- Data-quality / validation analog: catching bad records, stale sources, or a wrong number before it hits a report — analog to "validating datasets and catching issues before they affect reporting."

- Quantitative coursework (stats, calc, econ) visible in Education; GPA on the page; class-year `Expected May 2028`.

- Voice-AI, audio-DSP, or embedded C++ as the **lead** with no analytics analog — systems depth can support autonomy-company credibility but must not bury the DA spine.

- Invented Snowflake, Databricks, Copilot, Fusion, Tableau, Mode, Sigma, Looker, ThoughtSpot, Power BI, ERP, MES, or Zipline factory systems (`resume.md` §8 fabrication smell).
