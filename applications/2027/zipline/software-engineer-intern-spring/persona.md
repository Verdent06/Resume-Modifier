# Software Engineer Intern (Spring 2027) at Zipline

## Role Summary

Zipline is hiring a Spring 2027 Software Engineer Intern (January 2027 – April 2027, full-time, onsite South San Francisco, $50/hr with possible relocation support, housing stipend, overtime, and paid sick time) to own critical features across consumer mobile and web apps — from design through deployment and iteration. The JD surface is full-stack product engineering: React Native mobile, Python and Go backend services, cross-functional collaboration, and user-facing features that are fast and customer-grounded. The company identity is autonomous logistics at global scale: drone delivery, fleet operations, and mission-critical real-world systems — not a generic CRUD internship at a logistics label.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** autonomy / autonomous logistics
- **track_divergence:** true

The resume spine must pass a full-stack SWE screen (`resume.md` Part III §12; `recruiting.md` Part III §11): JD languages demonstrated through bullets, shipped product surfaces, backend ownership, and deployment discipline. Robotics/autonomy (`recruiting.md` §14) is the company differentiator, not the screen track — the JD does not test ROS, perception, or controls. Because Zipline's engineering identity is autonomous real-world systems, the page also needs prominent systems/real-world depth (reliability, hardware-adjacent or safety-critical software, C++/Python under constraint) without letting research-only or controls-only framing displace the product-engineering spine.

## Team & Bar

The reader is a Greenhouse-era human screen for a B-tier intern cohort (~3–8%; bottleneck: take-home + project defense). Zipline's funnel is practical, not OA-gated: resume screen → recruiter → resume deep-dive / tech screen → substantial take-home → final loop with project presentation (`companies.md` B-tier Zipline; `recruiting.md` Part I: startups/mid-size Greenhouse, a human reads the PDF early). The bar is evidence of building and shipping software users touch, with CS fundamentals visible in architectural decisions (`recruiting.md` §11: one or more genuinely engineered, shippable products narrated decision-by-decision), plus enough real-world systems credibility to feel credible at a company whose product is autonomous delivery. Intern eligibility is a hard knockout (`recruiting.md` §8): completed second year of undergraduate studies. This posting is Spring 2027 (Jan–Apr), distinct from the Summer 2027 term.

## Screen Criteria

- Full-stack evidence through bullets: web or mobile client work, backend APIs/services, and deployment — not Skills-line keyword stuffing alone (`resume.md` §2: keywords through use).
- JD languages the candidate can actually interview in must appear in project or experience context, not Skills only. Python is a floor signal. TypeScript/React client depth supports the mobile/web mandate; Go is named on the JD but is not a binary knockout if the rest of the product-engineering spine is strong. React Native is named; React/TypeScript web is the honest mapping when native is absent.
- Strong signals: end-to-end feature ownership, product-minded trade-offs, polyglot backend depth, measurable user or operational impact, and real-world systems discipline (reliability, latency, safety boundaries, hardware-software adjacency).
- Differentiator (secondary read, not the spine): autonomy-adjacent or real-world/safety-critical systems depth visible in the top half — without turning the page into a robotics-research resume (`recruiting.md` §14 as company identity, not as the intern screen).
- Anti-patterns: notebook-only ML without delivery; club-growth narrative without engineering depth; generic technology lists; a page that reads purely as robotics research with no consumer/product engineering surface; a page that reads purely web with zero systems/real-world adjacency at an autonomy company.
- When track diverges, the first-read should still say "ships product software" while a secondary read registers autonomy or real-world systems depth.
