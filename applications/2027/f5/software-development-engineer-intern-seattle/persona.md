## Role Summary

A paid, Seattle-based, full-time F5 Summer Internship Program SDE seat (12 weeks, Summer 2027). Interns contribute to real product development: design, implement, and test code; analyze requirements; integrate components; write technical documentation; sit in design and code reviews; explore data-driven solutions with the project team. Surface work is generic intern SWE — backend, DevOps, or new tools — on systems that **deliver and secure apps and APIs**. Company identity is application delivery / cybersecurity (`companies.md`: F5 ADSP / BIG-IP / NGINX family). This posting is **RP1039073 Seattle only** — not San Jose **RP1039076**, not Cork, not Tel Aviv WAF/WAAP or DevOps interns.

## Team & Bar

The reviewer is a B-tier F5 intern screener (`companies.md`: 3 rds · Easy–Med · HackerRank **[directional]** · no intern sys design · bottleneck: **OA then tech** · ~8–12%). Resume job: survive the ~7-second scan and look like someone who already writes **Python** against a real API or service, with a CI/Docker analog if honest, then clear the OA and 1–2 coding interviews. Recruiter voice: CS fundamentals plus engineers who ship tested, reviewable code — not "have they configured a load balancer" and not "did they publish an ML paper."

Eligibility is a knockout: US-enrolled bachelor's/master's; graduate **December 2027 – June 2029**; **two** additional quarters/semesters after the intern; ≤2 years similar FTE; Seattle onsite 12 weeks on one of three start windows. `Expected May 2028` is in window and leaves Fall 2027 + Winter 2028. GPA is not a JD floor. Comp **$42–$55/hr**. No clearance named.

Winning *kinds* of evidence: Python demonstrated in bullets, not Skills alone; a shippable product or production REST API with a database decision; unit tests / CI or a named production debug with a before/after; Docker or GitHub Actions through use (preferred DevOps, not a fake Kubernetes claim); intern-honest scope. Intern-stage weighting still favors engineered projects plus live GitHub (`resume.md` Part II intern).

## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names (**Python**). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). **Do not invent Go, Java, C#, C, Kubernetes, BIG-IP, NGINX, or Linux as a claimed OS internship.**
- Backend / full-stack delivery: services or APIs, data modeling or a real database, and a deploy or CI path, with at least one product defensible layer-by-layer (why this store, what failed, how it was tested or recovered).
- Testing and debugging through use: unit tests, CI, code review analog, or a named defect with a witness metric — the JD treats design/code reviews and testing as how work ships.
- Preferred DevOps as **honest use** (Docker, GitHub Actions / CI), not a homelab Kubernetes list with no demonstrated use (`resume.md` Part III §13 trap).
- Preferred AI/ML as **workflow or shipped application**, not an ML-research lead.
- Impact metrics (latency, failure-rate drop, hours saved, throughput) at roughly one per two bullets; titles the bullets can support.
- Class-year on the page: `Expected May 2028` satisfies December 2027 – June 2029 and two remaining terms.

**Anti-patterns:**

- Notebook ML / LoRA / LangGraph-as-research framing as the lead, as if this were an ML internship.
- Club-ops or community-growth without engineering the role tests.
- Skills-only Python (listed, zero bullet evidence) at a company where an OOP language is a floor signal.
- Inventing Go, Java, C#, C, Kubernetes, BIG-IP, or NGINX the work does not show.
- GTM / deal-sourcing as the lead at an app-delivery SDE company.
- Pure audio-DSP / embedded C++ as the identity for a generic backend/DevOps intern.
- Thin single-bullet filler that dilutes a shipped-API + deploy spine.
- Awards section or invented campus-lead titles.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
