# Summer 2027 Intern — Software Engineering at Western Digital (WD)

## Role Summary

A paid Summer 2027 onsite software internship at WD's San Jose Great Oaks HQ (other US sites exist; this req is San Jose). The posting is a catch-all early-career pipeline, not a single team: recruiting may place the intern on Applications Software, System Tools, Data Analytics, Firmware, or Systems Design & Integration. Surface work is design / develop / test / debug / optimize software in C, C++, Python, Java, Go, SQL, or JavaScript, plus collaboration with hardware and software engineers. Company identity is storage systems at hyperscale — HDD and the software that makes drives, arrays, and data-center infrastructure reliable — not a consumer web product or an OS/compiler research lab. An immediate opening is not guaranteed; the application is a routing form into anticipated intern seats.

## Track Decision

- **screen_track:** full-stack (general SWE)
- **differentiator:** storage / system software + hardware–software integration (C++ systems, performance, debugging; embedded-adjacent — not OS or compiler internships)
- **track_divergence:** true

The literal requirements test current-student status, CS fundamentals (debugging, DS&A, operating-systems *concepts*), and demonstrated use of one or more listed languages. That is a general SWE screen, so the resume spine is full-stack: shipped applications, APIs, data systems, Python/SQL/JavaScript-family delivery. The company-fit signal is system software that has to be correct under constraint — C++ performance/memory/concurrency, tools that make hardware usable, data pipelines at real scale — without fabricating operating-system or compiler internships the posting mentions as *possible* System Tools work. Firmware/assembly is a placement option, not the screen bar for this catch-all. Lead with the full-stack spine and keep C++ systems evidence prominent and deep.

## Team & Bar

The reviewer is a B-tier storage-company university recruiter (SmartRecruiters; 2–3 rounds; Easy–Med; no standard OA on the US careers FAQ; bottleneck: resume; ~8–12%). They route a generic intern resume onto an applications, tools, data, or firmware team. What wins: listed languages shown inside bullets, not Skills alone; a shipped application or data pipeline with ownership and impact metrics; and enough C++/systems discipline to be believable next to storage hardware. Recruiter voice is practical — "can this person write, debug, and ship software that talks to real systems?" — not "did they intern on GCC." Prestige is a tiebreaker. Enrollment through the internship plus a remaining term after Summer 2027 is a FAQ gate, not a resume line.

## Screen Criteria

- Demonstrates JD languages through use in bullets — especially C++ and Python, plus SQL or JavaScript-family where the work actually used them — not Skills-list only.
- Shows shipped application or data-system delivery (APIs, ETL, databases, test/debug, production ownership) so the Applications / Data Analytics routing is obvious.
- Keeps C++ systems / performance / memory / concurrency evidence visible in the top half as the storage-company differentiator, framed as engineering tools or real-time system software — never as an invented OS, compiler, or firmware internship.
- Uses impact metrics (latency, cost, failure recovery, scale, hours saved) rather than vanity counts.
- Anti-patterns: claiming OS/compiler/embedded-firmware internships the page cannot defend; a pure agentic/LLM product resume with no systems or application delivery; notebook ML; club-ops filler; Java or Go listed without bullet proof (they are optional "one or more," not a fabrication invitation).
