# Software Engineering Intern (Winter) at Datadog

## Role Summary

Winter 2027 SWE intern (Jan 4 – Apr 23, ~16 weeks, hybrid NYC or Boston) contributing to production systems that ingest and analyze metrics, logs, and application data in real time. Placement spans backend, frontend, infrastructure, data engineering, and developer tooling; the JD also names Kubernetes, distributed systems, cloud-native services, reliability/scalability work, and optional interest in Bits AI or developer platforms. JD surface is a generic SWE intern (CS fundamentals, coding in some language, 2028 FT start, AI-tooling curiosity). Company identity is observability — high-scale telemetry and cloud monitoring, not generic product CRUD.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** observability / high-scale telemetry / cloud monitoring
- **track_divergence:** true

The literal requirements test general SWE / full-stack fundamentals (`reference/resume.md` Part III §12, `reference/recruiting.md` Part III §11): degree, DS&A and software design, coding fluency, shipped work — not a Kubernetes/SRE filter and not an ML-training filter. Datadog's memorable identity is observability and telemetry at global scale (`reference/companies.md` A-tier Notes; `company.md`). Spine is full-stack shipping (APIs, pipelines, deploy, reliability). Differentiator stays prominent and deep: real-time or high-volume data processing, performance/reliability metrics, instrumentation, cloud-native/infra-adjacent systems the candidate can defend in a project deep-dive. Do not collapse into a pure frontend page or a notebook-ML / agentic-product page.

## Team & Bar

A-tier, selective; intern funnel in `companies.md` is **2 rounds, Medium, CoderPad, bottleneck = pre-tech screening**. A human reads the PDF early (Greenhouse). Recruiter voice: an intern who already ships production-shaped systems, can own a scoped project from design through deploy, and can survive a real project deep-dive (why this architecture, what breaks at 100×, how you measured it). Coding is LeetCode-medium with a systems flavor; Datadog-themed problems show up. Behavioral is a filter (`recruiting.md` Part I §6), not the differentiator. Eligibility is computed: 2028 FT target matches Expected May 2028. Hybrid NYC/Boston availability is a hard logistics gate, not a resume-content gate.

## Screen Criteria

- Production or production-shaped shipping: APIs, data pipelines, or services with a deploy path (cloud, containers, CI) demonstrated in bullets — not Skills-only.
- Scale, reliability, or performance evidence a recruiter can size in 30 seconds (latency, throughput, failure recovery, cost, volume) — maps to "performance, reliability, and scalability challenges" on the JD.
- Real-time or high-volume data processing visible in the top half — the observability differentiator — without turning the page into a specialist SRE or DSP-only resume.
- Full-stack spine: at least one product defensible layer-by-layer (backend/API, data store, a frontend or client, deploy). Breadth across the stack plus depth in one layer (`resume.md` §12).
- CS fundamentals on the page (DS&A coursework, software-design decisions in bullets) — the JD names them as a Who-You-Are floor.
- AI-assisted tooling or AI-in-the-product is a plus when tied to a shipped system; it is not the lead story for this req.
- Languages and infra keywords (Kubernetes, Docker, cloud, distributed systems) appear through use, not as an unbacked Skills dump. JD names no required language; polyglot proof still beats a list.
- Class-year on page: `Expected May 2028` satisfies the 2028 FT-start gate; internship term is junior-year winter with return to school.

## Anti-Patterns

- Leading with LoRA / LangGraph / agentic-AI product framing as if this were an ML internship.
- Club-ops, GTM/quant sourcing, or deal-flow work with no engineering the role tests.
- Kubernetes / distributed systems / observability named only in Skills.
- Frontend-only or notebook ML with no pipeline, deploy, or reliability story.
- Thin single-bullet filler that dilutes a production + systems spine.
- Claims the candidate cannot defend for 45 minutes in a project deep-dive.
