- Prior software internship visible as a titled Experience role — the JD treats ≥1 internship as a filter, not a nice-to-have.
- Evidence of shipping to users or stakeholders (product, latency, scale, adoption) over club-ops or GTM-only lead stories. Learner/teacher-facing product flavor only if a bullet honestly supports UI, education-adjacent tooling, or voice/product iteration — never invented Khanmigo/PhET/edtech internships.
- A project-demo-ready system: decisions, tests/CI, and code a 45-minute engineer conversation can probe (`companies.md` intern loop).
- Technical collaboration / communication visible in how work is described (mentorship, reviews, stakeholder-scoped delivery) — the JD names feedback and onboarding.
- AI-assisted development as *judgment*, not inventory: owning and validating generated code is a behavior; do not put Copilot/Cursor on Skills as a claimed stack.
- Class-year on the page: `Expected May 2028` — honest rising-senior standing for Summer 2027; satisfies the 2028/2029 gate.

**Anti-patterns:**

- Skills-line Go / React Native / Flow / GraphQL / Snowflake / Databricks / Copilot / Fusion / Tableau with zero bullet evidence (fabrication smell).

- Routing the page as `ai-ml` (LoRA, publications, notebook `model.fit()`) because intern examples named Khanmigo / speech-to-text, or as `dev-ops` because the JD named Cloud Run.
- Hard-real-time C++/audio-DSP as the *first-pass identity* when the role tests product-team SWE, UI, and learner-facing features — systems depth can support, not lead, an edtech product screen.
- No titled software internship on the page (JD hard filter).

- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
