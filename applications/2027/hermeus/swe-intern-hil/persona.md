# Software Engineering Intern (HIL) — Spring/Summer 2027 at Hermeus

## Role Summary

A paid, onsite Atlanta intern on Hermeus's Hardware-in-the-Loop team (Spring ~16 weeks January–April or Summer ~12 weeks May–August; $25–$33/hr by degree level). The intern configures, maintains, and troubleshoots HIL test benches; writes and expands automated tests and regression coverage for flight software and vehicle systems; keeps test stands ready (hardware config, software updates, calibration, documentation, issue resolution); debugs signal / hardware / software / communication faults across integrated systems; helps validate vehicle, avionics, and flight-deck controls; analyzes failures and supports root cause; documents procedures and infrastructure changes; collaborates with Flight Software.

JD surface vs company identity: the requirements literally test HIL benches, real-time simulation that connects hardware to software models, automated test/regression for flight software, embedded computers, and hardware/software-interface debug. That is a robotics-track screen (`resume.md` Part III §15; `recruiting.md` Part III §14) — sim + hardware–software boundary — not generic full-stack CRUD and not an ML-training req. Company identity is hypersonic / defense-aviation flight-software HIL in Atlanta (Quarterhorse / high-Mach unmanned aircraft). This lens is **Atlanta HIL only** — it is not the Los Angeles Modeling & Simulation intern and does not mix M&S, trajectory, or LA framing into the screen.

## Screen Criteria

- JD scientific-computing languages shown through use — Python and C++ in bullets, not Skills alone. Julia and MATLAB are JD alternatives; absence is not an auto-reject if Python or C++ carries real scientific/systems work. Do not claim Julia, MATLAB, Raspberry Pi, Arduino, or STM32 that the page cannot defend.
- Automated tests, scripts, or software tools demonstrated as engineering (coverage, regression, failure finding, infrastructure) — not a coursework list.
- Hardware–software interface, communication, or integrated-systems debug visible on the page. Embedded-computer *names* on the JD (Pi / Arduino / STM32) are examples of the class of work, not a license to invent them.
- Real-time / deterministic / constraint-bound systems evidence in the top half — HIL is simulation tied to hardware, not a notebook sim and not a consumer web app.
- Test-stand discipline: configuration, calibration, documentation, root-cause, keeping infrastructure reliable — shown through operational debug and owned test/tooling, not slogans.
- Impact metrics that size outcomes (latency, failure rate, recovery, scale, hours saved) rather than vanity counts (`resume.md` §4).
- Class-year on page shows current enrollment (`Expected May 2028` is a current student for a 2027 intern cycle). GPA ≥ 3.0 on the page.
