# Flight Software Engineering Intern (Summer 2027) at Muon Space

## Role Summary

A paid, full-time, on-site Summer 2027 internship (May–September window, $40/hr bachelor's) in Mountain View or San Jose writing software that runs on Muon satellites and the tools used to test it. The intern owns a scoped project through design, implementation, and testing — adding a spacecraft software capability, integrating a hardware component, developing simulations, or improving automated testing and developer tools. The JD surface is generic SWE: C / C++ / Python (or similar), data structures and algorithms, debugging, tests, and willingness to learn unfamiliar systems. Muon's identity is LEO constellation flight software and hardware-in-the-loop discipline — not consumer CRUD, not Applied Science / GNSS-R intern, and not a cloud-only rotation.

Form knockouts (U.S. Person / export control; on-site for the term) are apply-form gates, not resume lines. The live Greenhouse form currently asks Woodbridge, VA while the JD is San Jose / Mountain View — treat that as a shared-question leftover, not a second work site for this intern.

## Screen Criteria

- JD languages shown through use in bullets where the inventory supports them — C++ and Python at minimum — not only on the Skills line (`resume.md` §12 keywords-through-use). Do not invent C.
- General SWE delivery: APIs or services, data/storage, deployment or cloud, debugging/testing, and end-to-end ownership of something used by others.
- Differentiator visible in the top half: real-time constraints, lock-free / zero-alloc / deadline discipline, or hardware-adjacent debug — without turning the page into a firmware/RTOS document the candidate cannot defend, or a consumer-SaaS page with zero systems adjacency.
- Automated tests, simulation-shaped validation, or a real-time safety / release checklist visible through use — the intern writes tests and uses sim or hardware to validate.
- Metrics that size real outcomes (latency, throughput, failure recovery, scale) rather than vanity counts or club-ops filler.
- Prior intern/co-op or technical project-team depth if the page can support it — ownership, not membership.
- Anti-patterns: Skills-only C++/Python; invented ROS, MCU, orbital mechanics, satellite internships, firmware titles, or clearance-in-hand; leading with LoRA / LangGraph / agentic product framing as if this were an ML intern; notebook ML; club-ops without engineering depth; a PE/GTM story that buries the C++ real-time and debug evidence the FSW screen actually tests.
