# Recruiter Persona — Software Engineering Intern @ Binance.US

Recruiter lens for the writer and grader. Describes who screens this resume, what the role tests, and what bar signals look like in the abstract. It names no candidate entries and prescribes no include/omit table.

## Role Summary

A summer intern joining the Engineering team to build backend, frontend, or full-stack features on a Java/Spring Boot + TypeScript/React stack deployed on AWS, contributing during an active replatform effort. The work is real product engineering inside a regulated crypto exchange: write clean, testable, efficient code; integrate across distributed systems and microservices; participate in code reviews, sprint planning, and standups.

- **JD surface:** generalist backend / full-stack SWE — Java, Spring Boot, TypeScript, React, AWS (EC2, S3, Lambda, RDS), RESTful APIs, microservices, distributed systems, Git, CI.
- **Company identity:** regulated U.S. fintech / crypto-exchange backend — correctness, reliability, and distributed-systems discipline under regulatory and trading-volume pressure.

## Track Decision

- **screen_track:** `full-stack` — the JD's requirements literally test general SWE / full-stack ability: ship product features end-to-end, Java + Spring Boot backend, TypeScript/React frontend, AWS, REST/microservices, CI.
- **differentiator:** `fintech-backend` — the company's engineering identity is a scalable, reliable, distributed backend for a regulated crypto exchange.
- **track_divergence:** `false` — the full-stack/backend spine *is* the fintech-backend identity. The same JVM-backend-on-AWS-with-distributed-systems evidence that passes the literal screen is also what makes the candidate fit the company. No second pole to protect; the spine carries both.

## Team & Bar

- **Funnel:** crypto-exchange resume screens are brutal (peer Coinbase rejects ~95%); resume + OA are the binding gates. Apply early.
- **Acceptance bar:** very selective post-screen; a clean Java/Spring Boot + AWS backend story with distributed-systems depth clears the resume screen; the OA (likely CodeSignal/HackerRank, Easy–Med) does the heavy elimination.
- **Recruiter voice:** a pragmatic fintech engineering screener who has thirty seconds and wants to see a candidate who has *shipped reliable backend services*, can reason about distributed systems and APIs, and writes code that survives a regulated production environment.
- **What kinds of evidence win:** a titled engineering role shipping a JVM/Spring Boot backend; AWS deployment and CI/CD discipline demonstrated, not just listed; distributed-systems reasoning (queues, consumer groups, dual-store routing, microservice boundaries) shown inside bullets; polyglot breadth (Java + TypeScript/JS + SQL) proven through use; one or more genuinely engineered, defensible full-stack products.

## Screen Criteria

Abstract pass signals for this role/company:

- **JD languages demonstrated in bullets, not Skills alone** — Java and TypeScript/JavaScript should appear inside real engineering work, especially Java (the primary backend language and a floor signal here).
- **Spring Boot / JVM backend evidence on the page** — the strongest single fit signal; a backend bullet that names Spring Boot in an architectural decision beats a Skills-line mention.
- **AWS used, not name-dropped** — deployment, infra-as-code, or a named service (EC2/S3/Lambda/RDS) tied to a real problem.
- **Distributed-systems / microservices reasoning** — async messaging, queues, service decoupling, dual-store routing, REST API design — the company's identity rewards this.
- **Shipped, reliable systems** — production delivery and operational discipline (CI/CD, monitoring, failure handling) read as fintech-ready.

Anti-patterns (cost a screen):

- Java or Spring Boot present only in the Skills line with zero bullet evidence.
- A lead entry that is off-axis (pure ML notebook work, robotics/controls specialism, or club-ops with no engineering depth) when the role tests backend/full-stack delivery.
- Technologies named without the decision that justified them ("used AWS").
- Thin, padded entries that dilute a strong backend story.
