## Screen Criteria (abstract)

Pass signals:
- End-to-end ML workflow on the page: data prep or training-set analog → model implementation or adaptation → held-out / statistical validation (`resume.md` §14; JD: clean training data, implement ML methods, validate with statistical techniques). Not a thin API wrapper.
- Python demonstrated through use in bullets, not Skills alone. JD or-list is Python / R / MATLAB; R and MATLAB are not exclusive gates.
- Named ML libraries through use where the candidate actually has them (Pandas, PyTorch). Do not invent scikit-learn, TensorFlow, Keras, or NumPy.
- A prototype or interface analog: dashboard, API, or interactive surface for exploring model output (JD: rapid PoCs; interfaces for exploring AI solutions).
- Metrics that size model quality or data impact (accuracy, R², faithfulness, hours saved, precision), landed as the closer (`resume.md` §4).
- Independent delivery plus stakeholder or distributed-team analog (JD: work independently; collaborate across disciplines, locations, backgrounds).
- Quantitative coursework (stats, calc) visible in Education.

Anti-patterns:
- Treating this as Intern Robotics Software Engineering: ROS/C++ SDLC lead with no ML workflow.
- Treating this as System Verification: test plans / sample sizes / defect management with no modeling.
- ML-research framing: publications, novel methods, notebook `model.fit()` with no validation and no prototype (`recruiting.md` §13 research vs applied split). This req is applied PoC data science in an AI CoE.
- Off-axis lead: pure frontend, pure audio-DSP, or club-ops fronting a data-science intern req.
- PyTorch / Pandas / ML claims only in Skills with no supporting system.
- Inventing Snowflake, Databricks, Tableau, Copilot, Fusion, scikit-learn, TensorFlow, Keras, NumPy, R, MATLAB, ROS, or a CORI/surgical-robot internship the page cannot defend.
- Metric-free architecture bullets the recruiter cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
