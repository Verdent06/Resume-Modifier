# Intern Robotics Software Engineering at Smith+Nephew

## Role Summary

A 12-week Summer 2027 internship (planned start May 2027) on the Robotics New Product Development team in Pittsburgh, PA. Surface work is the software SDLC on next-generation surgical robotics: review requirements, design, implement, unit test, integration test, write Robotics QMS documentation, and present the intern project to senior leadership. Company identity is regulated orthopaedic robotics (CORI handheld platform / Real Intelligence software) — not a consumer web product, not a ROS/autonomy research lab, and not a catch-all IT intern seat. The intern is matched to a named NPD project with a manager/mentor.

## Track Decision

- **screen_track:** `full-stack` (general SWE)
- **differentiator:** surgical-robotics NPD / medical-device software quality (C++ OOP, test, QMS documentation — not a fabricated robot-firmware or ROS internship)
- **track_divergence:** true

The literal requirements test current CS/CE undergraduate status, a 3.0 GPA preference, and preferred C++ plus other object-oriented languages, UML, prior intern/co-op, leadership/PM, and cross-functional delivery. That is a general SWE screen (`resume.md` Part III §12; `recruiting.md` Part III §11): ship, design, implement, and test software. It is **not** `robotics` as the pipeline defines it — the JD never names ROS/ROS2, Gazebo, SLAM, perception, controls, or sim. Do not retarget to an FRC/autonomy resume. The company-fit signal is C++ systems discipline and correctness-under-constraint next to a regulated surgical robot, without inventing UML-tool, medical-device, or embedded-firmware internships. Lead with the SWE spine **and** keep C++ OOP / real-time systems evidence in the top half.

## Team & Bar

The reviewer is a B-tier medical-device university recruiter (Workday; TA screen then hiring manager; 2–3 rounds; Easy–Med practical; possible HireVue / Modern Hire / psychometric per official careers page; bottleneck: resume + no-sponsorship knockout; ~10–15% peer Medtronic). They are staffing CORI NPD in Pittsburgh, not routing a generic IT intern. What wins: C++ and another OOP language shown inside bullets; a prior co-op/intern; design + unit/integration-test evidence; named defects and hard constraints; enough ownership to present to senior leaders. Recruiter voice is practical — "can this CS/CE intern write, test, and document C++ on a regulated product team?" — not "did they intern on a surgical robot." Prestige is a tiebreaker. Current CS/CE enrollment and no-sponsorship work auth are knockout gates, not resume lines. UML is preferred; absence is not a hard filter if OOP design is visible.

## Screen Criteria

- Demonstrates C++ through use in bullets — not Skills-list only — plus at least one other object-oriented language the page can defend (Python or TypeScript).
- Shows a prior intern/co-op or equivalent owned delivery so "previous applicable intern, co-op" is obvious in 30 seconds.
- Keeps C++ OOP / memory / concurrency / test-before-release evidence visible in the top half as the surgical-robotics differentiator, framed as tools or real-time system software — never as an invented medical-device, ROS, or firmware internship.
- Shows design + test/debug (unit/integration analog: safety checklist, CI, named production defects, hard-fail gates) rather than feature lists.
- Uses impact metrics (failure rate, latency, cost, qualification rate, speedup) rather than vanity counts.
- Anti-patterns: claiming ROS, UML tools, surgical-robot internships, firmware, Snowflake/Databricks/Tableau/Copilot/Fusion; a pure agentic/LLM product resume with no C++ or test/debug; club-ops filler listed as employment; notebook ML; C++ only in Skills.
