## Screen Criteria

**Pass signals (abstract):**

- Front-end through use: a real UI (React or Angular) inside bullets, not Skills-only (`resume.md` §2, §12). TypeScript covers the JD’s JavaScript requirement honestly; HTML/CSS on the Skills line **and** UI work in bullets.
- Git / development workflow through use (version control, CI, code on GitHub) — the JD’s version-control floor.
- Browser / UI debugging with a witness metric (failure-rate drop, frame-rate, main-thread time) — maps to “comfort with browser developer tools and debugging.”
- Shipped interface other people used: dashboard, visualizer, or public-facing web — analog to translating mockups into working components.
- CS fundamentals visible: DS&A coursework plus engineered work defensible in an Easy coding screen if invited.
- GitHub (or portfolio) on the page.
- Class-year on the page: `Expected May 2028` satisfies pursuing-a-degree for Summer 2027.

**Anti-patterns:**

- Invented **ARIA, WCAG certification, axe/Lighthouse-as-a-job, Vue, Next.js, Java, Snowflake, Databricks, Tableau, Copilot, Fusion, or Sentry** — banned; not honest inventory.
- Skills-line HTML/CSS/JavaScript/React/Angular with zero bullet evidence.
- Agentic-AI / LoRA / notebook-ML lead as if this were an ML-research intern seat.
- Hard-real-time C++/audio-DSP as the first-pass identity when the role tests HTML/CSS/JS UI.
- Invented mall/REIT, simon.com, or property-CMS experience because the company paragraph named shopping centers.
- Club-ops, community-growth, or GTM/data-consulting filler with no UI.
- Thin single-bullet entries that dilute a frontend spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
- Missing GitHub on the resume.
