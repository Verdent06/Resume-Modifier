# Software Engineering Intern – Summer 2027 at Medtronic

## Role Summary

A paid Summer 2027 onsite software internship at Medtronic's Fridley, MN hub (many other US sites exist; this req is Fridley). The posting is a catch-all early-career pipeline, not a single team: recruiting may place the intern on software development, cloud, quality, DevOps, systems, test, AI/data science, or firmware. Surface work is design / develop / test / debug / implement software components, tools, and utilities, plus cloud, V&V, SDLC, and data algorithms. Company identity is regulated healthcare technology — devices and the software around them — not a consumer web product and not a hardware/mechanical intern seat despite the medical-device parent. An immediate team match is not guaranteed; the application is a routing form into anticipated intern seats.

## Track Decision

- **screen_track:** full-stack (general SWE)
- **differentiator:** medical-device / healthcare technology / regulated software quality (test, debug, V&V, SDLC — not a fabricated device-firmware internship)
- **track_divergence:** true

The literal requirements test current-student status, a listed language (C / C++ / C# / SQL / JavaScript / Java / Python / Swift / HTML/CSS), and demonstrated software development, testing, or cloud/DevOps/AI project work. That is a general SWE screen, so the resume spine is full-stack: shipped applications, APIs, data systems, Python/SQL/JavaScript-family delivery. The company-fit signal is software that has to be correct — C++ systems discipline, test/debug evidence, production ownership — without inventing medical-device, Java, or firmware internships. Firmware is a placement option, not the screen bar. Lead with the full-stack spine and keep C++ systems evidence prominent and deep.

## Team & Bar

The reviewer is a B-tier medical-device university recruiter (Workday; 2–3 rounds; Easy; Aon SJT rather than a coding OA on the intern path; bottleneck: resume + Aon; ~10–15%). They route a generic intern resume onto an applications, cloud, quality, test, or firmware team. What wins: listed languages shown inside bullets, not Skills alone; a shipped application or data pipeline with ownership and impact metrics; enough C++/systems and test/debug discipline to be believable next to regulated products. Recruiter voice is practical — "can this person write, test, and ship software?" — not "did they intern on an insulin pump." Prestige is a tiebreaker. Graduation in the Winter 2027–Spring 2029 window and no-sponsorship work auth are knockout gates, not resume lines.

## Screen Criteria

- Demonstrates JD languages through use in bullets — especially C++ and Python, plus SQL or JavaScript-family where the work actually used them — not Skills-list only.
- Shows shipped application or data-system delivery (APIs, ETL, databases, test/debug, production ownership, cloud) so software / cloud / quality / test routing is obvious.
- Keeps C++ systems / performance / memory / concurrency evidence visible in the top half as the healthcare-device differentiator, framed as tools or real-time system software — never as an invented medical-device, OS-kernel, or firmware internship.
- Uses impact metrics (latency, cost, failure recovery, scale, hours saved) rather than vanity counts.
- Anti-patterns: claiming medical-device, Java, C#, Swift, or embedded-firmware internships the page cannot defend; a pure agentic/LLM product resume with no application delivery or test/debug; notebook ML; club-ops filler; listing Jenkins/GitLab/C without bullet proof.
