# Software Development Engineering Intern - 2027 at Expedia Group

Recruiter lens shared by the writer and grader. Abstract bar signals only — no candidate entry names, no include/omit table.

## Role Summary

A paid, hybrid, full-time Expedia Group SDE internship (Summer 2027; Austin / San Jose / Seattle). Interns design, develop, and test software components and services under guidance: clean maintainable code (unit tests, code reviews, debugging); low-level system design, API design, and data modeling; DSA/problem-solving for quality, performance, and reliability; collaboration with technical and non-technical partners. They leverage AI-driven systems/tools/workflows, including safely integrating or operating AI/ML-enabled solutions — as **developer workflow**, not as an ML-research seat. Surface work is high-volume scalable web applications and e-commerce: back-end supply and database functions through new UIs for **140+ branded travel sites**. Company identity is travel marketplace / large eng org (`companies.md`: "Travel; large eng org"). This US posting is generic SDE + AI tools — not a named Software Development / Data Engineering / Machine Learning Engineering specialization picker (those appear on APAC twins).

Do not lead as notebook ML, LoRA-research, LangGraph-as-the-job, or DSP-only C++.

## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names (**Python**). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). **Do not invent Java, Kotlin, Snowflake, Databricks, Copilot, Fusion, Tableau, Go, or React Native.**
- Backend / full-stack delivery: services or APIs, data modeling or a real database, and a deploy or CI path, with at least one product defensible layer-by-layer (why this store, what failed, how it was tested or recovered).
- Testing and debugging through use: unit tests, CI, code review analog, or a named defect with a witness metric — the JD treats these as how work ships.
- Web / e-commerce flavor on that spine: user-facing UI plus backend/API, scalable or high-volume language (latency, throughput, failure recovery) without claiming Expedia-scale traffic.
- AI-assisted development as a **workflow** (tools in a shipped pipeline), not an ML-research lead.
- Impact metrics (latency, failure-rate drop, hours saved, throughput) at roughly one per two bullets; titles the bullets can support.
- Class-year on the page: `Expected May 2028` satisfies December 2027 – July 2028.

**Anti-patterns:**

- Notebook ML / LoRA / LangGraph-as-research framing as the lead, as if this were an ML internship (AI tools ≠ `ai-ml` track).
- Club-ops or community-growth without engineering the role tests.
- Skills-only Python (listed, zero bullet evidence) at a company where a general-purpose language is a floor signal.
- Inventing Java, Kotlin, or Expedia product/stack depth the work does not show.
- GTM / deal-sourcing as the lead at a travel e-commerce SDE company.
- Pure audio-DSP / embedded C++ as the identity for a web/e-commerce intern.
- Thin single-bullet filler that dilutes a shipped-API + web-UI spine.
- Awards section or invented campus-lead titles.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
