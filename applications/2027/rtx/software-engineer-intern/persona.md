# Software Engineer Intern at RTX (Raytheon)

## Role Summary

This is a Summer 2027 onsite software engineering internship in Huntsville, AL supporting RTX's missile-defense and integrated air-and-missile-defense software programs. The intern works as a software developer and integrator on a team: performing development, integration, test, and documentation to keep hardware/software platforms operating; integrating applications from many sources and holding them to stability and utilization standards; writing glue software for new capabilities and testing; and adhering to accepted engineering standards — unit tests with high code coverage, code peer reviews, design reviews, and test plans. The JD surface is generic, disciplined software engineering: Java in a Unix/Linux environment (required), Python scripting and a JavaScript framework (AngularJS/VueJS), Git version control, and CI tooling (Jenkins/Maven/GitLab) preferred. RTX's engineering identity is mission-critical defense software where integration, reliability, and rigorous test/review discipline matter more than novelty.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** mission-critical defense integration & test discipline (Unix/Linux, integration of multi-source components, CI/coverage)
- **track_divergence:** false

The screen spine is full-stack/general-SWE because the required and preferred qualifications test general software development in a Unix/Linux environment, application integration, disciplined unit testing and code review, version control, and CI — not ML research, robotics, or SRE-only infra. The differentiator aligns with the same spine: production-grade software that is built, integrated across components, and held to a testing/review/documentation bar reads as mission-critical engineering, so no divergence.

## Team & Bar

The reviewer is a defense-prime engineering screener working a resume-first funnel (no OA; the resume is the gate) with a relatively generous offer rate for candidates who clearly fit. They are screening for a student who can develop and integrate real software in a Unix/Linux environment and hold it to a professional quality bar. Strong signals: software built and shipped on Linux/cloud (EC2/Docker/containers), real integration of components or applications from multiple sources into a working system, disciplined testing and CI (unit tests, pytest, GitHub Actions/Jenkins/Maven/GitLab), version control fluency, Python demonstrated through real backend/scripting work, a JavaScript framework (Angular/Vue) shown through real frontend integration, and any systems-level engineering rigor (build discipline, real-time safety, code review). Weak signals: skills-only language claims with no supporting work, notebook/ML-only work with no delivery or integration, club-ops without engineering substance, and entries without quantified impact. Note the required Java-in-Unix/Linux line: a screener at a Java-forward shop weights demonstrated general software-development-in-Linux and CI/test discipline highly, and Java specifically is a floor they may probe — a candidate strong on adjacent compiled/typed languages and CI/test rigor still reads as a fit for a trainable intern.

## Screen Criteria

- Demonstrates general software development in a Unix/Linux environment (cloud/Linux deployment, containers, or systems build) through real bullets, not a skills token.
- Shows integration work — wiring components, applications, or data sources together into a working, deployed system — the core of this "developer and integrator" role.
- Surfaces disciplined testing / CI evidence (unit tests, pytest, GitHub Actions / Jenkins / Maven / GitLab) tied to real delivery, matching the JD's coverage/review/test-plan bar.
- Demonstrates Python through real backend or scripting work, and (bonus) a JavaScript framework (Angular/Vue) through real frontend integration — both JD-preferred.
- Uses version control (Git) as part of real delivery.
- Production reliability, performance, or fault-tolerance metrics that prove mission-critical discipline.
- Anti-patterns: Java or a JD language present only in Skills with zero bullet evidence at a Java-forward shop; notebook ML with no delivery/integration; tutorial-grade or unquantified "built an app" claims; padded club/ops entries with no engineering the role tests.
