# Software Engineer Intern — Engineering Automation, Vehicle Engineering (Winter/Spring 2027) at Tesla

## Role Summary

Winter/Spring 2027 Software Engineer Intern on Tesla Vehicle Engineering's Design Technology team (req 279763), Palo Alto / Fremont / SF Bay Area, full-time on-site, January 2027 through ~May 2027 (or continuing into Summer 2027 if available), minimum 12 weeks. Interns ship web applications that automate or streamline the design process used by thousands of vehicle, battery, and manufacturing engineers — tools professional design engineers and program managers actually run. JD surface is full-stack web: React / Next.js / TypeScript and/or Python or Go APIs, PostgreSQL (complex SQL, views, functions, migrations), REST/gRPC, reusable frontend components, live-system debugging, CI/CD (Docker, Kubernetes, Jenkins preferred), cloud (AWS/GCP/Azure). Company identity is Tesla EV manufacturing plus this team's internal design-tooling mandate — not Autopilot/Dojo inference, not Tesla Energy UI.

## Team & Bar

Tesla is B-tier in `companies.md` (~5–8%; bottleneck = tech rounds). Funnel: resume screen → HackerRank OA (Medium; Codility also reported by cycle) → technical rounds → ownership/culture behavioral. Everyone who clears the OA still needs a Design Technology team-match; the resume's job is to look like someone who already ships production web tools, not to clear the OA. Recruiter voice: first-principles, bias for action, production-quality code, cross-functional with mechanical and design engineers. Strong signals: JD languages demonstrated inside bullets (TypeScript and/or Python — not Skills alone); a full-stack product defensible layer-by-layer (UI, API, Postgres, deploy); PostgreSQL/SQL through use; production delivery to real stakeholders; data-intensive apps; a live-debug story with a before/after number. Impact metrics (latency, failure rate, hours saved, scale) beat vanity counts. Behavioral is a filter (`recruiting.md` §6). Intern sys-design is not expected (`companies.md`: No).

## Screen Criteria

- Full-stack web delivery in bullets: a React/TypeScript (or equivalent web) UI, Python or similar APIs, a relational database, and a deploy/CI path — not Skills-only (`resume.md` §12). Breadth across the stack plus depth in at least one layer.
- PostgreSQL / SQL through use (queries, persistence, migrations-shaped work) — the JD names Postgres proficiency as a floor, not a nice-to-have.
- Production delivery: a titled engagement or live product other people actually run, with maintain-and-improve or stakeholder-handoff evidence — maps to "deliver web applications useful to diverse groups" and "work cross-functionally with mechanical and design engineers."
- Data-intensive application evidence (ETL, rankings, embeddings/search, scored pipelines) — the JD asks for data-intensive apps, not notebook analytics.
- Live-system debug: a diagnosed production defect with a before/after number (failure rate, cost, latency, FPS) — maps to "ability to debug live software systems" and "diagnosing problems in multi-layered enterprise applications."
- JD languages the candidate actually has (TypeScript, Python, C++) used inside architectural decisions. Do not invent Next.js, Go, Kubernetes, Jenkins, Redux, Drizzle, or gRPC to match preferred stack.
- Class-year on page: `Expected May 2028` plus a January 2027 start is junior-year winter/spring with return to school. JD has no class-year cutoff beyond current enrollment.
- CAD (SolidWorks / Catia) is preferred familiarity only — a honest Skills mention is enough; do not fake CAD-tooling product work.

- Invented Next.js, Go, Kubernetes, Jenkins, Redux, Drizzle, gRPC, or Catia on the page.
- Leading with LoRA / LangGraph / agentic-AI product framing as if this were an Autopilot or applied-ML internship.
- Leading with hard-real-time audio DSP / plugin systems as if this were embedded Autopilot.
- Skills-list stuffing of Tesla's preferred infra with zero backing bullet.
- Club-ops or GTM/quant deal-sourcing as the lead story for an internal-tools web intern.
- Pure frontend with no API/database, or backend-only with no UI a design engineer would open.
- Languages listed in Skills with zero bullet evidence (except CAD-as-preferred-familiarity).
