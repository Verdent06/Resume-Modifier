# Software Engineer Intern (Summer 2027) at Coinbase

Recruiter lens shared by the writer and grader. Abstract bar signals only — no candidate entry names, no include/omit table.

## Role Summary

Campus SWE intern on a Coinbase engineering team (Greenhouse **8168315** / PID **GETR-PSWE00US-Q326**). Twelve-week Summer 2027 hybrid internship: Product Group teams in San Francisco (Base, Consumer, Developer, Institutional, Platform) or Core teams in New York (Security, Enterprise Engineering). Interns write tested code that ships to production, take code review, own one scoped project end-to-end, and apply crypto/blockchain concepts on real systems that sit at web-scale applications and blockchain. JD surface is generic intern SWE: programming in **any language**, ability to decompose ambiguous work, and familiarity with **at least one of** web development, mobile, backend systems, or infrastructure. Responsible use of generative AI copilots (LibreChat, Gemini, Glean) with human-in-the-loop is a **workflow** requirement — not an ML-research mandate. Company identity (`company.md` / `companies.md`) is **fintech-backend / crypto-web-scale**: a regulated U.S. crypto exchange plus Base L2, custody, and developer APIs — not a trading desk, not a consumer-app startup, and not an LLM-research seat.

## Screen Criteria

**Pass signals (abstract):**

- Shipped full-stack or backend software: a real frontend or API surface, a persistence decision, and cloud/deploy (AWS/Docker/CI) tied to an outcome (`resume.md` §12). Tests, named debug, or code-review discipline matches "high-quality, well-tested code that ships to production."
- Keyword-through-use for web, backend, infrastructure, production, and testing — not Skills-only (`resume.md` §2). JD languages are "any"; do **not** invent Go, Rust, or Solidity to look crypto-native.
- CS fundamentals visible: DS&A coursework plus engineered work defensible in an Easy–Med CodeSignal OA (the post-screen equalizer).
- End-to-end ownership of a scoped project (the intern's 12-week shape): problem → implementation → launch, not club-ops.
- Finance-adjacent or high-reliability production flavor on that spine: APIs, data integrity, regulated or financial workflows, latency/cost defects with a before/after — memorable here without replacing the SWE spine.
- Generative-AI workflow as a **plus** only when already present in a selected bullet (e.g. Gemini via the `llm-apis` set). Never GitHub Copilot. Never an agentic-AI / LoRA lead as if this were an ML intern seat.
- Class-year on the page: `Expected May 2028` satisfies the FT-in-2028 form question and the open JD.

**Anti-patterns:**

- Invented Go, Rust, Solidity, Coinbase employment, or crypto-protocol work that is not on the page.
- Invented Snowflake, Databricks, Fusion, Tableau, or **GitHub Copilot** (JD copilots are LibreChat / Gemini / Glean — workflow, not a resume token).
- Agentic-AI / LoRA / notebook-ML as the first-pass identity because the JD mentions generative AI tools.
- Hard-real-time C++/audio-DSP as the lead story when the role tests web/backend/infra product SWE.
- Club-ops, community-growth, or coursework-only framing with no shipped application.
- Thin single-bullet entries that dilute a production full-stack spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
- Skills-line technologies with zero bullet evidence where the recruiter would treat them as floor signals.
