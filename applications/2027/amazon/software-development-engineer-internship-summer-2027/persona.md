# Software Development Engineer Internship - Summer -2027 (USA) at Amazon

Recruiter lens shared by the writer and grader. Abstract bar signals only — no candidate entry names, no include/omit table.

## Role Summary

A paid, in-person, 12-week Amazon SDE internship (majority Summer 2027, May/June–Aug/Sep; Winter 2027 also possible; Fall 2027 not selected). Interns collaborate with cross-disciplinary Amazonians to design, build, and operate products and services; break ambiguous problems into solvable components; contribute to scalable, reliable services (distributed-systems scope varies by team); do code reviews including of AI-generated code; write technical documentation; use GenAI tools while critically validating output; write clean maintainable code with design patterns; work Agile + CI/CD with operational responsibilities including on-call; and practice operational excellence (monitoring, troubleshooting, production issues). JD surface is generic intern SDE: 18+, enrolled CS/CE/DS/IS/STEM, at least one of Java / Python / C++ / C# / Go / Rust / TypeScript, DS implementation / algorithms / OOP, AI-assisted development tools, 40 hrs/week, 12-week max, conferral Oct 2027–Sep 2029, remaining term after internship. Preferred: prior technical internship or projects, cloud (preferably AWS), SQL and NoSQL, AI productivity tools, OSS, version control, SDLC, problem decomposition, ownership design-to-operation, communication, learn/adapt. Specialty interest areas (ML, distributed systems, databases, quantum, networking, query processing, automated reasoning, embedded, data engineering, mobile, games) are **optional team-placement hints**, not an ML-research requirement. Company identity is high-volume Big Tech SDE: scalable services, operational excellence, ownership from design through operations.

## Track Decision

- **screen_track:** `full-stack`
- **differentiator:** scalable services / distributed systems / operational excellence
- **track_divergence:** false

Requirements literally test general SWE (`resume.md` Part III §12; `recruiting.md` Part III §11): a general-purpose language, DS&A, OOP, shipped projects, CI/CD, operational habits. That routes to `full-stack` (default for generic SDE). Do **not** route `ai-ml` because Machine Learning appears as an optional specialty interest, and do **not** route `dev-ops` because CI/CD / on-call / monitoring are how Amazon SDEs operate services, not a platform-SRE exclusive test.

The company's dominant engineering identity is the same family as the JD: **scalable services / operational excellence / ownership**. Differentiator is flavor on the full-stack spine (production APIs, reliability, design-to-operation), not a second track. Do not lead as notebook ML, LoRA-research, LangGraph-as-research, or DSP-only C++.

## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names (**Python**, **TypeScript**, **C++**). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). **Do not invent Java, Go, Rust, Kafka, or AWS-as-deep-expert.** Cloud/containers only at routine level (EC2, S3, Docker, GitHub Actions) tied to real work.
- Backend / full-stack delivery: services or APIs, a real database (SQL / NoSQL), and a deploy or CI path, with at least one product defensible layer-by-layer (why this store, what failed, how it was tested or recovered).
- Operational excellence flavor on that spine: monitoring, troubleshooting, production issues, CI/CD, or design-to-operation ownership — Amazon SDE identity, not a DevOps-track pivot.
- Testing / version control / clean-code evidence on the page (unit tests, GitHub Actions, or equivalent) — the JD treats Agile + CI/CD and code review as how work ships.
- AI-assisted development as a **workflow** (critically validating generated code), not an ML-research lead.
- Impact metrics (latency, throughput, failure recovery, cost, scale) at roughly one per two bullets; titles the bullets can support.
- Class-year on the page: `Expected May 2028` satisfies Oct 2027–Sep 2029 conferral and remaining-term after Summer 2027.

**Anti-patterns:**

- Notebook ML / LoRA / LangGraph-as-research framing as the lead, as if this were an ML internship (specialty interest ≠ track).
- Club-ops or community-growth without engineering the role tests.
- Skills-only languages (Python/TypeScript/C++ listed, zero bullet evidence) at a company where a general-purpose language is a floor signal.
- Inventing Java, Go, Rust, Kafka, or deep AWS (ECS/EKS/Lambda/DynamoDB) the work does not show.
- Claiming Amazon employment, Leadership Principles as Skills, or distributed-systems depth the page cannot defend.
- GTM / deal-sourcing as the lead at a Big Tech SDE company.
- Thin single-bullet filler that dilutes a shipped-API + scalable-services spine.
- Awards section or invented campus-lead titles.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
