# Software Engineer Intern — Agentic Creation (TTEP) at TikTok

## Role Summary

A Summer 2027, 12-week campus internship on TikTok's Agentic Creation team (TikTok Effect Platform / TTEP), the group that runs the creator-facing creation ecosystem — creation tools, website, and in-app surfaces — spanning rewards, inspiration, activity, analytics, and badge modules. The JD surface is a fullstack SWE req (frontend, backend, big data, DS&A in a mainstream language); the team's actual mission is building AI agents and an operation platform (agent servers, prompt management, skill workflows, MCP tool establishment, knowledge-base solutions) to improve creator acquisition, activation, retention, and operational efficiency. Interns work cross-functionally with PMs, product ops, and data scientists and are expected to move business metrics (publish rate, viral supply, creator retention).

## Track Decision

- **screen_track:** full-stack
- **differentiator:** agentic/LLM-orchestration systems — agent servers, prompt/skill-workflow engineering, MCP tooling, knowledge-base/RAG solutions
- **track_divergence:** true

The literal minimum-qualification bar (DS&A fluency, one mainstream language among Golang/JavaScript/C/C++/Python, "fullstack systems" spanning frontend/backend/big-data) is a generic full-stack screen. But this specific team's dominant engineering identity — stated in both the "About the Team" framing and every core responsibility bullet — is agentic AI infrastructure: agent servers, prompt management, skill workflows, MCP tools, and knowledge-base/RAG patterns. The resume leads with the full-stack spine (frontend-through-backend-through-data delivery) and keeps agentic/LLM-orchestration evidence prominent and deep near the top — it does not collapse into either a pure-web resume or a narrow ML-research resume.

## Team & Bar

The reviewer is a TikTok/ByteDance campus recruiter screening a high-volume intern pipeline (per `reference/companies.md`: 3–4 rounds, Med–Hard, HackerRank/OA-gated, bottleneck is resume + LC). Per `reference/recruiting.md` Part I §1, for big-tech-scale pipelines the OA is the highest-elimination stage and the resume's depth mostly wins team-match *after* the OA clears — so the resume needs to survive the screen cleanly and then read as a strong match for this specific team during team-match. They reward evidence of: real DS&A/language fluency demonstrated through shipped work (not a bare Skills-line claim), genuine end-to-end fullstack delivery (frontend, backend, data pipeline), and — since this team is building agent infrastructure, not just consuming an LLM API — production-grade agentic/LLM-orchestration engineering (pipeline architecture, eval/validation harnesses, structured data layers) reads as a strong company-fit signal that most generic full-stack applicants won't carry.

## Screen Criteria

- At least one JD-listed language (Golang, JavaScript, C/C++, Python) demonstrated through real engineering decisions in bullets, not only in the Skills line.
- Genuine fullstack delivery visible across the page — frontend, backend/API, and a data layer — not a single-layer specialist page.
- Agentic/LLM-orchestration substance near the top of the page: an agent pipeline, prompt/workflow engineering, an eval or validation harness, or a structured data/knowledge-base layer — the closer this reads to "built an agent system in production," the stronger the company-fit signal.
- Anti-patterns: notebook-only ML with no delivery path; an LLM feature described as a thin API call with no orchestration/architecture behind it; club-ops or membership padding without engineering depth; a resume that reads purely as generic CRUD/full-stack with zero agentic-systems signal at a team whose entire identity is agentic AI.
- Product sense / cross-functional signal: evidence of working directly with non-engineering stakeholders (PM, ops, data science, or an external client) to ship something real, not just solo technical execution.
