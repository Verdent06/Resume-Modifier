## Screen Criteria (abstract)

Pass signals:
- Shipped full-stack: frontend framework + REST/backend + persistence or deploy, narrated decision-by-decision (`resume.md` §12). Keyword-through-use for Python, C++, SQL, HTML/CSS, Angular (JS-family), REST — not Skills alone (`resume.md` §2).
- OOP proof in bullets for languages the candidate actually has. JD prefers Java; **Python and C++ also satisfy the OOP floor**. Do **not** invent Java.
- SQL through use (queries, persistence, data access) — preferred on the JD.
- Production support / customer-service analog: a user-facing failure, investigation, fix, witness metric — the JD's triage/troubleshoot-with-end-users line.
- Stakeholder-scoped delivery analog to product enhancement + Agile SDLC.
- Metrics that size impact (error-rate, hours saved, latency, throughput), landed as the closer (`resume.md` §4).
- Class-year on the page: `Expected May 2028` — Junior for a June 2027 intern after two years of CS.

Anti-patterns:
- Skills-line Java with no bullets (fabrication smell).
- Claiming Spring, SOAP, AngularJS, or DB2 the page cannot defend.
- Inventing insurance policy-admin platforms or a prior carrier internship.
- Leading as ML-research / LoRA / notebook `model.fit()` when the role tests OOP, SQL, full-stack shipping, and prod support (`recruiting.md` §13 applied vs research split).
- Off-axis lead: hard-real-time C++/audio-DSP as first-pass identity on an enterprise Java policy-admin intern req (C++ OOP as supporting evidence is fine; DSP-as-the-story is not).
- Club-ops filler without engineering depth.
- Metric-free architecture bullets the recruiter cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
