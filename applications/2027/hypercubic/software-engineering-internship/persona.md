# Software Engineering Internship at Hypercubic

## Role Summary

A flexible/rolling software engineering internship (summer, semester-long, or co-op), full-time in-person in San Francisco, at a YC F25 three-person startup building agentic AI for COBOL/mainframe modernization. The intern owns a high-impact project end to end: rapid prototyping, then polish; shipping AI-driven systems that can span agent workflows, evals, program-analysis tooling, backend infrastructure, and user-facing features; turning ambiguous problems into experiments and working systems; contributing to testing, reliability, and code-quality standards; working directly with the CTO and with SMEs/customers in banking, insurance, airlines, and utilities. The JD surface is generic SWE intern fundamentals. The company identity is agentic AI plus program analysis for legacy/mainframe systems.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** agentic AI / COBOL-mainframe modernization / program analysis
- **track_divergence:** true

The requirements literally test programming fundamentals, ambitious shipped work, comfort with ambiguity, prototype-then-polish, and clear technical communication — generic SWE intern filters, not ML frameworks, training, inference, or data-pipeline bars. Work spanning agents, evals, program-analysis tooling, backend, *and* user-facing features is still a generalist intern shape, so the spine is full-stack (`recruiting.md` §11; `resume.md` Part III §12). COBOL, compilers, and program analysis are preferred, not a requirement filter. The differentiator is the company's YC identity: agentic products for mainframe/COBOL understanding and modernization. The resume leads with a full-stack spine and keeps agentic-pipeline / eval / systems-depth evidence prominent and deep — it does not flip the page into an ML-research or COBOL-specialist document.

## Team & Bar

The reviewer is a founder/CTO at a ~3-person pre-seed team reading the PDF on Ashby — startup funnel, human-first, no published intern OA (`recruiting.md` §5). The bar is evidence the candidate can own a project end to end, prototype quickly then harden, and communicate clearly under ambiguity. Strong signals: shipped production systems with metrics; agentic workflows and eval/test discipline (not a single LLM call); backend infrastructure plus user-facing features on the same page; reliability/code-quality habits (tests, measured defects, CI). Preferred-but-not-required: production-grade software, TDD/property-based testing, compilers/program-analysis/HPC, enterprise constraints. Anti-patterns: notebook ML without delivery; Skills-only agent keywords; club-ops without engineering; a page that never shows both a backend and a UI; COBOL named without any systems depth to stand on.

## Screen Criteria

- Programming fundamentals shown through real shipped systems — APIs, data layers, services, or products with a user — not coursework lists or Skills-only languages.
- End-to-end ownership: an entry that reads as scoped, built, and delivered, matching "own and ship a high-impact project."
- Agentic workflow and/or eval evidence visible in the top half (divergence): multi-step orchestration, adversarial/eval gates, or measured quality lifts — not "AI" as a label.
- Prototype-then-polish: a defect-fix, reliability, or test/CI story so the page is not only happy-path architecture.
- Backend infrastructure *and* user-facing feature evidence somewhere on the page (JD work spans both).
- Quantified impact (latency, cost, accuracy, throughput, scale) so systems-thinking claims can be sized.
- JD names no required languages; do not treat COBOL as a filter. Preferred compilers/program analysis/HPC may appear as systems depth, never as invented COBOL.
- Anti-patterns: tutorial-grade projects; metric-free ambitious claims; leading with an off-axis lane that buries agentic/systems signal; thin filler entries.
