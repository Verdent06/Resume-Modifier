## Screen Criteria (abstract)

Pass signals:
- Python demonstrated through use in bullets, not Skills alone. It is the named language floor.
- Applied AI fluency: agents, orchestration, embeddings, on-device or served inference, or an eval loop — not a thin API wrapper.
- ML fundamentals with implementation: a trained/adapted/served model (framework fine-tune, classical model, or on-device runtime) plus held-out or before/after evidence (`resume.md` §14 end-to-end workflow).
- Shipped full-stack or production API (frontend framework + backend + persistence, or a deployed service) kept in the lead window — the retail-scale differentiator, not a second spine.
- Container and cloud through use (Docker, AWS) — analog to the JD's Docker / system-enhancement body without inventing Kubernetes or Cosmos DB.
- Large or messy data handled in a pipeline (ingest → normalize → serve) with a witness metric.
- JS-family / React through use when present in inventory — analog to the role-body frontend stack. Do not invent Node/Java/Spring.
- Metrics that size impact, landed as the closer (`resume.md` §4).
- Class-year on the page: `Expected May 2028` vs Summer 2027 penultimate intern. GPA 3.66 is a genuine signal.

Anti-patterns:
- Inventing Java, Scala, Spring Boot, Cosmos DB, Kubernetes, Snowflake, Databricks, Copilot, Fusion, or Tableau (`resume.md` §8 fabrication smell).
- Senior-level Walmart-scale ownership, team leadership, or "millions of customers" claims the page cannot defend. Title says II; the candidate is an undergrad intern.
- Notebook ML / `model.fit()` with no delivery, no eval, no serving.
- Off-axis lead: pure audio-DSP / embedded C++ or club-ops fronting an applied-AI + retail-systems intern.
- AI/ML/Python/Docker/React claims only in Skills with no supporting system.
- Metric-free architecture bullets the recruiter cannot size.
- Treating this as a generic full-stack intern and burying applied AI, or as an ML-research intern and burying shipped systems.
