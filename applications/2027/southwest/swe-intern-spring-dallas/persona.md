## Screen Criteria

**Pass signals (abstract):**

- At least one JD language through use in bullets — Python is the honest overlap; TypeScript/JavaScript-family UI or services count as the JS analog. Skills-only language lists fail `resume.md` keyword-through-use.
- Generic SWE delivery: design → implement → test/document analog → something other people used (`resume.md` §12; JD duties).
- Production APIs (REST) and/or cloud (AWS S3/EC2-class) inside architectural decisions, not a bare Skills token.
- Data transformation / ETL / JSON-shaped ingest→normalize→serve — analog to enterprise integration and financial-data processing without naming Workday/SIRAX.
- Real-time, fault-tolerance, or production-incident recovery visible enough that a NOC/ops screener does not see a pure CRUD tutorial.
- Impact metrics (latency, failure-rate, hours saved, throughput, precision, scale) as closers (`resume.md` §4) — not uptime/LOC/coverage vanity.
- Class-year on the page: `Expected May 2028`; GPA if ≥ 3.5. GitHub on the resume.
- Preferred recent titled SWE intern/co-op signal when the page can support it.

**Anti-patterns:**

- Invented **Java, C#, Node, Workday, Kafka, SOAP, XSLT, SIRAX, BRIM, Copilot, Fusion, Snowflake, Databricks, Tableau** — not in inventory; fabrication smell (`resume.md` §8).
- Skills-line Python/JavaScript/AWS/REST with zero bullet evidence.
- Leading as autonomy/robotics, notebook ML, or LoRA/LangGraph-as-identity when this screen tests application systems for an airline Technology org.
- Hard-real-time C++/audio-DSP as the first-pass identity when the differentiator is enterprise integrations + ops reliability (systems discipline can support; it must not replace APIs/AWS/data-transform).
- Club-ops, community-growth, or coursework-only filler in the lead window.
- Thin single-bullet entries that dilute a full-stack spine.
- Missing GitHub; year-only graduation date; two-column/ATS-hostile layout.
