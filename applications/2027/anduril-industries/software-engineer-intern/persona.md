# 2027 Software Engineer Intern at Anduril Industries

## Role Summary

A paid, in-person, 12-week Summer 2027 software engineering internship across Atlanta, Boston, Costa Mesa, Irvine, Reston, and Seattle. The intern supports software already deployed to customers, writes code that scales mission capability, collaborates across teams to plan/build/test complex functionality, creates and analyzes debugging/monitoring metrics, and triages issues to root-cause. The JD surface is generic SWE: algorithms, data structures, storage systems, cloud infrastructure, front-end frameworks, and polyglot proficiency (C++, Go, Rust, Java, Python). Anduril's identity is defense autonomy — Lattice OS, sensor fusion, networking, software that has to work in the field — so the company-fit signal is mission-critical systems discipline, not a consumer web app.

## Team & Bar

The reviewer is an A-tier defense-tech screener on Greenhouse before a Medium HackerRank and a practical loop whose bottleneck is a 4-hour onsite (`companies.md`: 3 rds · ~3–5%). Recruiter voice: can this intern ship and debug software other people depend on, in a mission-oriented culture (bias for action, low ego, high ownership)? Strong signals: production-style ownership with metrics; JD languages demonstrated inside bullets (especially C++ and Python — the autonomy/CS pair `recruiting.md` §14 names); storage/cloud/frontend evidence so the generic SWE screen clears; visible real-time, systems, or field-debugging depth so the page is memorable past a generic full-stack pile. Prestige is a tiebreaker, not a gate (`recruiting.md` §8). U.S. Person is an apply-form knockout, not a resume line.

## Screen Criteria

- JD languages shown through use in bullets — C++ and/or Python at minimum — not only on the Skills line. Go/Rust/Java are named; absence in bullets is a gap only if the page also fails to prove polyglot depth another way.
- Broad SWE fundamentals on the page: APIs or services, storage/data, cloud or deployment, and some frontend/client work (`resume.md` §12 keywords-through-use).
- Metrics that size real outcomes (latency, throughput, cost, failure recovery, scale) — debugging/monitoring is a listed job duty, not a nice-to-have.
- Differentiator visible in the top half: real-time constraints, C++ systems, operational root-cause, or hardware-adjacent discipline — without turning the resume into a robotics-only document.
- Ownership and bias for action via shipped systems, defect/root-cause stories, and cross-team or stakeholder delivery — not club-ops or membership filler.
- Anti-patterns: Skills-only polyglot stuffing; notebook ML or demo robotics with no engineering; a consumer-SaaS page with zero systems/C++ signal at an autonomy company; metric-free architecture claims; tutorial-grade projects.
