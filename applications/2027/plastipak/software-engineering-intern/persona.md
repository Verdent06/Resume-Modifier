## Screen Criteria

Pass signals:
- Shipped application delivery (frontend + backend/API + data store + deploy) so the intern-SWE flavor is obvious (`resume.md` §12).
- Data-integration / pipeline evidence (ingest, normalize, serve, keep data fresh) mapping to Technical Data Integration without fabricating plant-floor SCADA/PLC.
- Troubleshooting and reliability: diagnosed defects, failure recovery, cost/latency/error-rate wins with metrics as closers (`resume.md` §4).
- Optional ML/AI as **explore** — applied pipelines or inference in a product, not notebook `model.fit()` as the identity.
- JD names no languages; Python/TypeScript/SQL/C++ through use still beats Skills-only lists. Keyword-through-use for manufacturing software, applications, data integration, machine learning, AI.
- Metrics that size impact (hours saved, failure rate, throughput, qualification lift), not vanity counts.
- Live GitHub on an intern engineering resume (`resume.md` §3).

Anti-patterns:
- Leading as a PLC/OT/controls technician or stuffing SCADA/FactoryTalk/SAP/C# the page cannot defend.
- Leading with C++ audio DSP as the identity — this req is plant applications / data integration, not a synth plugin shop (systems depth may support, not headline).
- Notebook ML or agentic-AI product framing as if this were an ML-research intern.
- Club-ops filler; metric-free architecture the recruiter cannot size.
- Inventing Snowflake, Databricks, Tableau, Copilot, Fusion CAD, Java, C#, or plant-DCS internships.
- Skills-list keyword stuffing with no backing bullet.
