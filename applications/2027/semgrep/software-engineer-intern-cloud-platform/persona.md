# Software Engineer Intern, Cloud Platform at Semgrep

## Role Summary

11-week paid Cloud Platform intern in the San Francisco office, 5 days/week, starting Monday May 24, 2027 or Monday June 14, 2027 ($2,400/week). The intern ships features on Semgrep's full-stack AppSec product — Python, PostgreSQL, TypeScript, React — so teams can integrate Semgrep into existing workflows or so services stay reliable at scale. Surface work is product engineering: user/product/design collaboration, metrics and experiments on core workflows, code review, a closing demo. Company identity is developer-first code security (SAST / SCA / Secrets), not a generic CRUD shop and not the Program Analysis intern (OCaml / Haskell / compilers).

## Track Decision

- **screen_track:** full-stack
- **differentiator:** appsec / developer-security platform
- **track_divergence:** true

JD requirements literally test shipping in a Python / PostgreSQL / TypeScript / React codebase plus dynamic-language fluency (`resume.md` Part III §12 / `recruiting.md` Part III §11). There is no compiler, program-analysis, or ML-training bar, so the spine is not `ai-ml` and not systems/C++. The differentiator is Semgrep's product identity: a developer-security platform (workflow integrations, triage, reachable-vuln quality, guardrails in the write path). The resume leads with a full-stack spine and keeps developer-enablement / workflow / quality-and-reliability evidence prominent and deep — it does not flip the page into AppSec research or OCaml.

## Screen Criteria

- Full-stack shipping with web, API, and a persistence or deploy path in bullets — not Skills-only (`resume.md` §12). Breadth across the stack plus depth in at least one layer.
- Python and TypeScript (or JavaScript-family) used inside an architectural decision. PostgreSQL / React through use when present. Do not invent Ruby, PHP, OCaml, Haskell, Snowflake, Databricks, Copilot, Fusion, or Tableau.
- Differentiator visible in the top half: developer-enablement, workflow integrations, triage/quality, or reliability of a user-facing service — not a buried security label and not a compiler-track pivot.
- Quantified impact (latency, cost, failure rate, throughput, precision/quality, scale) so “ship features” and “remain reliable” can be sized.
- User or stakeholder contact somewhere on the page (scoping with a real consumer of the work, not only solo architecture).
- Anti-patterns: tutorial-grade projects; Skills-only Python/TypeScript/React; notebook ML without delivery; leading with an off-axis systems/C++ or research-compiler lane; thin filler; club-ops without engineering.
