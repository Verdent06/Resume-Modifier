# Software Engineer Intern at Axon

## Role Summary

This is a Summer 2027 software engineering internship (May–August 2027) based in Seattle or Boston, hybrid Tue–Fri onsite at $45/hr + bonus. Interns own end-to-end features on public-safety software alongside Product and Design, participate in code reviews and architecture meetings, and present to executives in a 12-week mentored program. The JD surface is generic software engineering: OO-language proficiency, shipped features, collaboration, and database familiarity — not ML research or specialized autonomy. Axon's engineering identity is mission-critical public-safety cloud software at scale (evidence management, records, real-time operations on AWS) where reliability, auditability, and production delivery to real users are the differentiator.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** public-safety / mission-critical cloud software
- **track_divergence:** false

The screen spine is full-stack because required qualifications test CS fundamentals, at least one OO language (Java, Python, Scala, Go, C#), and end-to-end feature delivery — not ML training, robotics, or infra-only SRE. The differentiator aligns with the same spine: production cloud SaaS with REST/API layers, databases, and reliability evidence that reads as software serving high-stakes users, not hobby projects.

## Team & Bar

The reviewer is screening for a large public-company intern cohort where candidates must show they can ship production-oriented code with mentoring — APIs, databases, cloud deployment, and measurable reliability or performance wins. Strong signals include Python or TypeScript demonstrated through backend or product bullets, REST or service-layer ownership with real deployment context, SQL/NoSQL evidence through use, prior SWE internship or co-op depth, Git and CI/CD tied to delivery, and fault-tolerance or latency metrics that prove mission-critical discipline. Weak signals include skills-only language claims, notebook ML without delivery, club ops without engineering substance, or entries that lack quantified impact.

## Screen Criteria

- Demonstrates at least one JD OO language (Python strongly; TypeScript/C++ acceptable) through product or backend bullets, not only in the skills line.
- Shows end-to-end feature delivery: REST/API work, database integration, and cloud or container deployment with metrics.
- Ties SQL or database technology to real queries, schemas, or search — not a lone Skills token.
- Surfaces production reliability or performance evidence (latency, failure rates, throughput, cost reduction) appropriate to public-safety-grade software.
- Prior SWE internship or co-op reads as engineered delivery, not resume padding.
- Avoids tutorial-grade projects, vague "built an app" claims without system depth, or AI/agentic work with no production or reliability signal.
