# Software Engineering Intern at CTGT

## Role Summary

This is a Summer 2027, onsite software engineering internship in San Francisco for an early-stage AI infrastructure company building deterministic governance layers for AI workflows. The JD surface is broad software engineering: build and ship features across backend services and product surfaces, write code that holds up under real load, work from design through delivery, and make progress through ambiguity. CTGT's company identity adds an AI-governance lens: the work ships into high-stakes model environments where correctness, auditability, and performance are non-negotiable.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** AI workflow governance / reliable AI infrastructure
- **track_divergence:** true

The screen spine is full-stack/general SWE because the required qualifications test Python, JavaScript, Git, basic AWS/GCP workflows, product/backend delivery, and communication rather than ML model training or research credentials. The differentiator is AI governance infrastructure, so the strongest resume still needs visible evidence of reliable AI-adjacent systems, human approval or audit boundaries, and production-minded backend/cloud decisions.

## Team & Bar

The reviewer is screening for a small, venture-backed startup where interns are expected to own meaningful projects and work directly with senior engineers. The bar is not a keyword-matched student resume; it is evidence that the candidate can ship correct, maintainable software across the stack without constant scaffolding. Strong signals include Python and JavaScript shown through real product work, backend services that handle concurrency or load, cloud/deployment fluency, system decisions explained clearly, and AI-adjacent reliability work that can survive a technical deep dive.

## Screen Criteria

- Demonstrates Python and JavaScript/TypeScript through product or backend work, not only in the skills line.
- Shows shipped full-stack or backend systems: APIs, data stores, client surfaces, deployment, and operational ownership.
- Ties cloud/Git workflows to real delivery, such as CI/CD, AWS provisioning, Docker deployment, or migration discipline.
- Keeps AI-governance/reliable-AI evidence visible in the top half without turning the resume into a pure ML research page.
- Uses metrics for latency, throughput, scale, or reliability so "real load" reads as measured engineering, not aspiration.
- Avoids tutorial-grade frontend, vague AI claims, or club leadership that lacks engineering depth.
