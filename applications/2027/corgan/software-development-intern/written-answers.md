### Essay (500 words or less) — live prompt from the public PDF

I want to write software that other professionals actually run — not demos, not notebooks. Corgan's Business Technology intern is that job in an architecture firm: web apps, APIs, and dashboards that change how architects and designers deliver airports, data centers, schools, and hospitals.

I do not have a design degree and I have not used Revit or BIM. What I do have is a habit of sitting with non-engineers, learning the painful manual step, and replacing it with something they can keep using after I leave.

At Michigan Data Consulting I was the only engineer on a five-month contract with the Michigan Campaign Finance Network. Researchers were spending about two hours per committee copying irregular Excel exports. I built a Requests and Pandas pipeline that ingested filings directly — about 800 hours of pulls across 400 PACs — and shipped a Flask REST API on AWS EC2 into their public research workflow. The users were investigators, not other software people. That is the closest analog I have to partnering with architects and project managers: requirements come from the work, not from a ticket template.

The front-end side of the same habit showed up at CaseStudyPrep. Angular was silently dropping WAV uploads; 27 percent of files never made it to S3. I wrote RxJS that detects an expired presigned URL, regenerates it mid-flight, and negotiates MIME types, then moved audio off the UI thread into a Web Worker so the visualizer stayed at 60 FPS. Reliability and a usable interface were the product, not a model card.

I also care about the data layer those interfaces sit on. SignalWeaver is a React and TypeScript dashboard over FastAPI and Postgres, with Docker Compose and GitHub Actions on main — the dashboard-plus-API-plus-CI shape this intern posting describes. Vylet is a live lead-sourcing product ($1,500 MRR) where I had to diagnose a name-collision bug that was throwing away good records; the fix moved qualification from 79 percent to 89 percent without changing volume. That is the post-deploy loop: ship, watch it fail on real data, patch it.

Architecture and interior design are not my major. They are a domain where small software mistakes waste expensive people and where good tools are invisible when they work. I want the Dallas IT Pathways seat because the users are designers making places other people will occupy, and because the stack — web, APIs, SQL, Git, some applied AI — is work I can defend in an interview instead of pretending I already know C# or CAD.
