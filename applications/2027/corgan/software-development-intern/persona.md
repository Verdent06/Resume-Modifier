# Software Development Intern at Corgan

## Role Summary

Summer 2027 paid Software Development Intern on Corgan's Business Technology / IT Pathways team in Dallas (10–12 weeks, primarily onsite). JD surface is intern full-stack in an architecture firm: web applications and tools for design workflows, project management, and client visualization; APIs and integrations; interactive dashboards; Agile (sprints, code review, CI/CD); optional applied AI/ML (computer vision, generative design, spatial analysis, predictive modeling) and innovation PoCs (AR/VR, IoT, cloud-native). Company identity is AEC — airports, data centers, education, healthcare, commercial buildings — so the intern writes software *for architects and designers*, not studio drawings. This is corporate IT product work, not a design-studio intern and not an ML-research rotation.

## Track Decision

- **screen_track:** full-stack (JD requirements test a modern language, CS fundamentals, web apps/APIs; preferred HTML/CSS/JS frameworks, SQL, Git, cloud)
- **differentiator:** internal-product engineering for an architecture firm (AEC Business Technology / design-technology)
- **track_divergence:** false

The screen spine follows `resume.md` Part III §12 — a shippable web app or API with a database, a real front end, cloud deploy, and full-stack breadth defended decision-by-decision. The differentiator is domain flavor on the same spine: tools used by non-engineer professionals, dashboards that change a decision, APIs between business systems. Applied AI/ML is preferred-plus, not the lead identity.

## Team & Bar

Corgan is unrated in `companies.md` — a large employee-owned architecture firm (Dallas HQ; Architectural Record 2026 #4). Business Technology hires interns who can ship reliable web apps and services, show at least one JD language in bullets (not Skills-only), and read as collaborative with architects, designers, and project managers. iCIMS campus ATS; human screen is the front door (`recruiting.md` Part I §5 mid-size / non-tech-tech). No named OA. Scholarship packet is a hard process gate on the JD ("formal scholarship submission"). U.S. work authorization is required on the scholarship eligibility line. Class-year gate: at least one semester remaining after Summer 2027.

## Screen Criteria

- Web front-end proof: JavaScript/TypeScript with React *or* Angular demonstrated in a bullet, not just listed in Skills.
- Full-stack shipping: a REST / Web API plus a real front end plus a database, with outcome metrics and a deploy or CI step.
- Database evidence: SQL / relational design in bullet context.
- Stakeholder delivery: working with non-engineer partners (researchers, fund principals, paying clients) maps onto partnering with architects and designers.
- At least one modern language through use (Python, JavaScript/TypeScript, C++, etc.). C# / Java / .NET are preferred-plus; polyglot OOP plus willingness to ramp is sufficient — do not invent them.
- Git / CI visible through use (GitHub Actions counts).
- AI/ML, data visualization, and cloud (AWS) as bonus signals through use, not as a research-intern pivot.
- Class-year on page must show current enrollment (`Expected May 2028` satisfies "one semester remaining after Summer 2027").
- Portfolio/GitHub link is an explicit apply step — a live GitHub on the header is load-bearing.

## Anti-Patterns

- Pure agentic-AI or notebook-ML framing with no web/API/DB delivery for a generic full-stack intern req.
- C++/embedded or audio-DSP as the first-pass identity — systems depth is a plus but must not be the spine.
- Skills-line stuffing for C#, Java, .NET, Azure, or CAD/BIM with zero bullet evidence.
- Thin single-bullet entries that dilute a strong full-stack spine.
- Claiming architecture, Revit, or BIM experience the candidate does not have.
- Solo-only framing with no collaboration/stakeholder signal, against a JD that foregrounds architects, designers, and business partners.
