# Software Engineer Intern/Co-op - Spring 2027 at SoloPulse

## Role Summary

A paid Spring 2027 software intern/co-op at an Atlanta dual-use radar startup. The intern designs, develops, tests, and deploys software across frontend and backend, writes and optimizes algorithms, and engineers low-latency solutions to proprietary computational operations. The JD surface is generic SWE (Python + C++, FE+BE, architecture, ownership). SoloPulse's identity is radar / RF sensing for civilian safety and military autonomy — so the company-fit signal is real-time and low-latency systems discipline, not a consumer web app.

Prestige is a tiebreaker, not a gate (`recruiting.md` §8). Atlanta-area and clearance-*ability* are apply-form questions, not resume lines.

## Screen Criteria

- JD languages shown through use in bullets — Python **and** C++ — not only on the Skills line.
- Broad SWE fundamentals on the page: frontend or client work, backend/API, and some deploy or architecture decision (`resume.md` §12 keywords-through-use).
- Metrics that size real outcomes (latency, failure recovery, throughput, cost, scale) — low-latency compute is a listed job duty, not a nice-to-have.
- Differentiator visible in the top half: real-time constraints, C++ systems, lock-free or zero-allocation discipline, or operational root-cause — without turning the resume into a hobby-DSP or radar-claim document.
- Ownership and autonomous delivery via shipped systems and diagnosed defects — not club-ops or membership filler.
- Anti-patterns: Skills-only C++/Python stuffing; CUDA / PyTorch / OpenGL / ThreeJS claimed without use; a consumer-SaaS page with zero systems/C++ signal at a radar company; metric-free architecture claims; tutorial-grade projects.
