# Software Developer Intern at Kimley-Horn

## Role Summary

Summer 2027 in-office Software Developer Intern on Kimley-Horn's corporate Technology & Innovation team, supporting development, enhancement, and post-deployment maintenance of internal full-stack software products used by a ~10,000-person civil-engineering firm. JD surface is classic full-stack web: HTML/CSS/JavaScript/TypeScript with Angular on the front end, relational + NoSQL databases (MS SQL Server, NoSQL), and object-oriented backend (C#, .NET). Company identity is internal-product engineering for practicing civil engineers — workflow automation, system/CAD integrations, geospatial web tools, and applied-AI (RAG / multi-agent) features — so end-to-end delivery, iterative enhancement, and working directly with non-engineer stakeholders matter as much as raw feature velocity.

## Track Decision

- **screen_track:** full-stack (JD requirements literally test web front end + REST/Web APIs + relational/NoSQL databases + OOP)
- **differentiator:** enterprise/internal-product full-stack for a civil-engineering consultancy (Microsoft ecosystem, geospatial + applied-AI flavor)
- **track_divergence:** false

The screen spine follows `resume.md` Part III §12 — a shippable web app or API with a database, a real front end, cloud deploy, and full-stack breadth defended decision-by-decision. The differentiator is domain flavor on the same spine: stakeholder-facing delivery, iterative bug-fix/enhancement work, geospatial or applied-AI signal registers company fit without pivoting the page off full-stack evidence.

## Team & Bar

Kimley-Horn is an unrated (not in `companies.md`) large, stable engineering consultancy with a strong "best place to work" culture — the corporate SWE team hires interns who can ship reliable web apps and services, demonstrate at least one JD web language in bullets (not Skills-only), and read as collaborative, communicative self-starters comfortable in an iterative development environment. In-office in Cary/Raleigh, NC. No employer sponsorship offered — U.S. work authorization is a hard knockout (candidate needs none). Posting is ~2 days old; per `recruiting.md` §8 the early-applicant pool is smaller, so timing is real leverage.

## Screen Criteria

- Web front-end proof: TypeScript/JavaScript (and ideally Angular) demonstrated in a bullet, not just listed in Skills.
- Full-stack shipping: a REST / Web API plus a real front end plus a database, with outcome metrics and a deploy step.
- Database evidence: relational design/queries in bullet context; NoSQL / key-value store as a plus signal.
- Stakeholder + iterative delivery: working with non-engineer partners, shipping enhancements and bug fixes, delivering inside an engagement window — reads directly onto the JD's collaboration and iterative-development bar.
- OOP / backend competency demonstrated through built services, not claimed in isolation; C#/.NET is a preferred plus, so polyglot OOP depth (Python/C++/TypeScript) plus willingness to ramp reads as sufficient.
- Production ownership over coursework demos — contracted delivery, co-op shipping, or a live product with users.
- Class-year on page must show current enrollment (`Expected May 2028` satisfies Summer 2027 eligibility).

## Anti-Patterns

- Pure agentic-AI or notebook-ML framing with no web/API/DB delivery depth for a generic full-stack intern req.
- C++/embedded or audio-DSP lead when the role tests web stacks — systems depth is a plus but must not be the spine.
- Skills-line stuffing for C#/.NET or SQL Server with zero bullet evidence at a company where those are floor-preferred.
- Thin single-bullet entries that dilute a strong full-stack spine.
- Solo-only framing with no collaboration/stakeholder signal, against a JD that foregrounds teamwork and client-service communication.
