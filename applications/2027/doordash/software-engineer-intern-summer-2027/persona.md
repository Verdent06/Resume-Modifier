# Software Engineer, Intern (Summer 2027) - US at DoorDash

Recruiter lens shared by the writer and grader. Abstract bar signals only — no candidate entry names, no include/omit table.

## Role Summary

A Summer 2027 paid, in-person, 12-week product-engineering internship (May or June start) at a DoorDash office in New York, San Francisco, Sunnyvale, Los Angeles, or Seattle. Interns develop, maintain, and ship on teams that run a 24x7 global infrastructure system for a three-sided marketplace of consumers, merchants, and Dashers. JD surface is generic intern SWE: CS degree, databases (AWS, SQL), algorithms and data structures, one OOP language (Python / Java / Kotlin as examples), clean code, version control, unit testing. Preferred: a prior SWE internship, responsible use of AI-powered tools (evaluate outputs — not a named Copilot skill), efficiency/scalability/stability, large-scale web applications, monitoring / live deploys / CI, real-time technology problems, SOA / APIs / system design, plus project/research/hackathon/campus-org/TA work. Company identity is on-demand logistics at marketplace scale — product engineers who ship user-friendly flows **and** scalable backends — not an ML-research seat and not a mobile-Kotlin Android intern.

## Track Decision

- **screen_track:** `full-stack`
- **differentiator:** on-demand logistics / three-sided marketplace (consumers, merchants, dashers)
- **track_divergence:** true

Requirements literally test general SWE (`resume.md` Part III §12; `recruiting.md` Part III §11): OOP language, databases, testing, version control, CS fundamentals. That routes to `full-stack` (default for generic product SWE). Do **not** route `ai-ml` because "AI-powered tools" appear as a preferred habit, and do **not** route `dev-ops` because CI / live deploys / monitoring are preferred operating practices, not the JD's exclusive test.

The company's dominant engineering identity is **reliability-at-scale logistics for a three-sided marketplace** (real-time matching-shaped problems, APIs, live systems). That identity is distinct from generic CRUD web, so divergence is true: the resume leads with the `full-stack` spine **and** keeps real-time, reliability, and production-API evidence prominent in the lead window. Do not lead as notebook ML, LoRA-research, or DSP-only C++.

## Screen Criteria

**Pass signals (abstract):**

- Polyglot proof for languages the candidate actually has that the JD names or implies (**Python** as the OOP floor; TypeScript/C++ as inventory languages used in an architectural decision). Keyword-through-use in bullets, not Skills-only (`resume.md` §2). **Do not invent Java or Kotlin.**
- Backend / full-stack delivery: services or APIs, a real database (SQL / AWS), and a deploy or CI path, with at least one product defensible layer-by-layer (why this store, what failed, how it was tested or recovered).
- Testing / version control / clean-code evidence on the page (unit tests, pytest, GitHub Actions, or equivalent) — the JD treats these as how work ships, not a Skills footnote.
- Real-time, reliability, or live-system evidence visible in the top half (company-fit differentiator: latency, failure recovery, concurrency, recurring workers) without turning the page into an ML-research resume or a DSP-specialist resume.
- Impact metrics (latency, throughput, failure recovery, cost, scale) at roughly one per two bullets; titles the bullets can support.
- Class-year on the page: `Expected May 2028` satisfies Fall 2027–Summer 2028.

**Anti-patterns:**

- Notebook ML / LoRA / agentic-AI framing as the lead, as if this were an ML internship.
- Club-ops or community-growth without engineering the role tests.
- Skills-only languages (Python/Java/Kotlin listed, zero bullet evidence) at a company where the OOP language is a floor signal.
- Inventing Java, Kotlin, Kotlin Android, Go, Kafka, GitHub Copilot, Snowflake, Databricks, Tableau, or Fusion CAD.
- Claiming DoorDash, Dasher, or logistics-marketplace employment the page does not show.
- GTM / deal-sourcing as the lead at a product-SWE logistics company.
- Thin single-bullet filler that dilutes a shipped-API + real-time spine.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact (`resume.md` §4).
