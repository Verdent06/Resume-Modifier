# Software Engineer Intern at Hadrian

## Role Summary

Paid, on-site Los Angeles Software Engineer Intern on the team building the software backbone of Hadrian's autonomous factory (Ashby req, Engineering / Product / Design). Work is real production software: internal tooling, dashboards, automation systems, backend services, APIs, and data pipelines used by engineering, operations, and quality — plus features that improve visibility into production workflows, capacity, and program status. Code ships. The JD surface is generic SWE (Python / TypeScript / Go, backend/APIs/data engineering, production software). Hadrian's identity is autonomous factories for aerospace and defense manufacturing (Opus factory OS, Factory-as-a-Service) — so the company-fit signal is industrial/factory-ops software, not a consumer app and not a robotics/CNC specialist page.

## Track Decision

- **screen_track:** full-stack
- **differentiator:** autonomous-factory / aerospace-defense manufacturing software
- **track_divergence:** true

Required qualifications test general SWE / full-stack shipping (`resume.md` Part III §12 / `recruiting.md` Part III §11): one or more of Python, TypeScript, Go; familiarity with backend, APIs, or data engineering; production software that ships. They do not name ROS, CNC, perception, or model-training as filters, so the spine is not `robotics` or `ai-ml`. The differentiator is Hadrian's A-tier autonomous-factory / A&D manufacturing identity (`companies.md`: Opus, internal tools/APIs/pipelines/dashboards). The resume leads with a full-stack backend/product spine and keeps production-systems / pipeline / factory-ops-adjacent software prominent and deep — it does not flip into a robotics-only or consumer-SaaS page.

## Team & Bar

The reviewer is an A-tier defense-manufacturing screener on Ashby before an unpublished intern loop (`companies.md`: resume-first; no named OA; bottleneck resume + onsite/mission; ~3–5% directional). Recruiter voice: can this intern ship and debug software operators and program teams actually run, in a fast, ambiguous factory environment? Strong signals: JD languages demonstrated inside bullets (Python and TypeScript — Go is listed on the req but is not a floor for a candidate who does not have it); shipped backend services, APIs, pipelines, or dashboards; production debugging / owned failure with a before/after; visible excitement for manufacturing, aerospace, defense, or industrial systems without fake machine-shop claims. Impact metrics (hours saved, failure rate, latency, scale) beat architecture-only prose. Behavioral is a filter (`recruiting.md` §6). Prestige is a tiebreaker (`recruiting.md` §8). U.S. Person / ITAR is an apply-form knockout, not a resume line. Graduation window December 2027–June 2028 is a binary gate (`recruiting.md` §1, §8).

## Screen Criteria

- JD languages shown through use in bullets, not Skills alone. Python and TypeScript are the languages that must appear in architectural decisions. Go is named on the JD; absence is not a reject if the page never claims it.
- Shipped backend / APIs / data pipelines / dashboards / internal tools — the intern's actual job, not a skills list (`resume.md` §12 keywords-through-use).
- Production debugging or owned failure: a diagnosed defect with a before/after number (failure rate, cost, latency, qualification rate). Maps to "code will ship" and "surface technical risks."
- Differentiator visible without fake CNC/ROS: production systems, pipelines, ops dashboards, or industrial-adjacent software in the top half — not a robotics specialist document and not a consumer-SaaS page with zero ops/debug signal.
- Ownership and follow-through via titled delivery to real stakeholders, code-review-shaped collaboration, and clean metrics — not club-ops or membership filler.
- Class-year on the page: `Expected May 2028` sits inside the JD window (December 2027–June 2028). On-site LA willingness is an apply-form fact, not a resume claim.

Anti-patterns:

- Python (or TypeScript) only on the Skills line.
- Claiming Go — or Snowflake, Databricks, Tableau, Copilot, Fusion, Sentry — that the page cannot defend.
- Notebook ML or LoRA/agentic framing as the lead story for a factory-product intern.
- Club-ops, GTM/quant deal-sourcing, or consumer-SaaS with zero production-debug or ops-visibility signal as the opening read.
- Metric-free architecture claims; tutorial-grade projects; Skills stuffing of factory buzzwords with no backing bullet.
