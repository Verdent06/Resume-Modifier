# Databricks

Databricks builds the Data + AI Platform — a unified lakehouse for data apps, analytics, and agents used by 20,000+ organizations, including 70% of the Fortune 500. Interns ship features into that platform across full stack, backend, infrastructure, systems, tools, cloud, databases, and customer-facing products; the JD is a generic SWE intern req, not an ML-training or Spark-specialist seat. `reference/companies.md` A-TIER Notes flag data/AI infra, a $134B valuation with an IPO imminent, and a concurrency round that is genuinely hard — that identity is the differentiator after a language + DS&A screen.

## Quick Facts

- **Tier:** A-TIER — Excellent / Strong Signal (`reference/companies.md`)
- **HQ / offices:** San Francisco, CA (HQ); 30+ offices globally. This req: Bellevue, WA; Mountain View, CA; San Francisco, CA. This apply: Bellevue.
- **Valuation / signal:** ~$134B; IPO imminent (`companies.md`); category leader in data/AI infrastructure vs Snowflake-class peers
- **Product focus:** Databricks Data + AI Platform (lakehouse / unified data and AI infrastructure) — intern work is platform features, not a product-usage internship
- **Intern comp (2027 SWE intern, Winter):** Bellevue, WA $51.50–$60/hr; SF Bay Area $54–$60/hr (JD)
- **Work model:** Paid Winter 2027 internship (January–April only); onsite at the applied office; dedicated mentor; 2027 intern cohort. One application per 30 days; apply to a single location.
- **Clearance / eligibility:** Graduate fall 2027 or spring 2028 with CS, Engineering, or related. Export-controlled technology/source code access is at employer discretion (license may not be applied for). Winter term only — not Summer/Fall.

## Interview Process

| Stage | Format | Notes |
| ----- | ------ | ----- |
| Resume screen | Human + Greenhouse ATS | University recruiting; one app / 30 days; location chosen at apply. Grad window is a knockout. |
| OA | CodeSignal (`companies.md`) | Intern-cycle reports: ~70 min, 4 coding problems, proctored, ~7-day deadline; GCA-style Easy→Med-Hard. Highest *volume* intern filter in candidate writeups — treat as a delta on the doctrine bottleneck, not a replacement. |
| Tech phone | CoderPad (intern reports: 1–2 × 45–60 min) | LC medium; data-processing slant (arrays, hashing, trees/graphs) |
| Virtual onsite | 3–4 rds total (`companies.md`) | Med–Hard coding + **concurrency (single-machine, ~60 min)** + light/single-machine sys design. Concurrency is the doctrine bottleneck. |
| Behavioral | Values / HM fit | Collaboration on ambiguous problems; why Databricks; project ownership |

**Estimated funnel:** 3–4 rounds · Med–Hard · CodeSignal · Yes (single-machine) · Bottleneck: concurrency round · <3% (`reference/companies.md` Databricks row)

## Stack & Hiring Signal

- **Languages:** JD examples of a general-purpose language: Python, Java, or C++. Placement spans full stack / backend / infra / systems / tools / cloud / databases — not a single-language floor beyond "can implement."
- **Domains:** Data and AI infrastructure, lakehouse platform, distributed data systems, cloud, databases, developer tools, customer-facing platform products. Do **not** treat Spark, Unity Catalog, Lakehouse-as-skill, or Databricks product experience as a screen requirement — this is a generic SWE intern posting at a data-infra company.
- **What wins:** A full-stack intern spine (`resume.md` Part III §12 / `recruiting.md` Part III §11) with Python and/or C++ shown in bullets (Java only if the candidate actually has it), DS&A/OOP visible as coursework plus design decisions, and shipped data-pipeline / backend / systems depth so the page is memorable at a lakehouse company. Do not invent Databricks product claims. After the PDF, CodeSignal then the concurrency round are the binding filters (`companies.md`; intern OA reports).
