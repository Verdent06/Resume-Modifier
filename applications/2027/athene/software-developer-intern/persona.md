## Screen Criteria (abstract)

Pass signals:
- Shipped small-to-medium applications: frontend framework + backend/API + persistence or deploy, narrated decision-by-decision (`resume.md` §12). Keyword-through-use for Angular (plus), TypeScript, Python, SQL, AWS — not Skills alone (`resume.md` §2).
- Testing / defect diagnosis: named failure, investigation, fix, witness metric — the JD's application-testing and "resolve routine programming issues" line.
- SDLC / documentation analog: scoped delivery, design-or-code documentation, standards, or stakeholder/PM fact-finding analog.
- Polyglot proof for languages the candidate actually has. JD names C# / .NET MVC as *plus* — **do not invent C#**. TypeScript / Python / SQL / C++ through use beats a Skills-only claim.
- Finance-adjacent or complex business-workflow evidence as the company-fit differentiator (not invented annuity-admin platforms).
- Cloud through use (AWS). Azure is plus, not a fabrication target.
- Metrics that size impact (error-rate, hours saved, latency, throughput), landed as the closer (`resume.md` §4).
- Class-year on the page: `Expected May 2028` — honest Junior / rising-junior standing for Summer 2027; Fall 2027 enrollment is the JD gate.

Anti-patterns:
- Skills-line C# / .NET MVC / Azure / Copilot / Snowflake / Databricks / Tableau / Fusion with zero bullet evidence (fabrication smell).
- Inventing those tools, or claiming Athene / annuity / policy-admin internships the page cannot defend.
- ML-research / LoRA / notebook `model.fit()` as the first-pass identity when the role tests application development, testing, and SDLC (`recruiting.md` §13 applied vs research split). GenAI is a bonus, not the job.
- Off-axis lead: hard-real-time C++/audio-DSP or club-ops fronting an enterprise financial-services application-development intern req.
- Metric-free architecture bullets the recruiter cannot size.
- No live GitHub on an intern engineering resume (`resume.md` §3).
