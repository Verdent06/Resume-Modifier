## Screen Criteria

**Pass signals (abstract — the writer discovers which entries carry them):**
- Python shown inside real ML, LLM, or data/model-pipeline work, not only the Skills line (`resume.md` keyword-through-use).
- End-to-end applied ML: data preparation → model or LLM system → evaluation → some delivery/monitoring analog (`resume.md` §14; `recruiting.md` §13 applied profile).
- Generative AI / LLM applications or agentic workflows with an eval harness, held-out test, or faithfulness/accuracy lift — not a buzzword line.
- Search, retrieval, ranking, or recommendation-shaped work as on-axis product ML, when present.
- Production or deployment signal: cloud (AWS analog is enough), serving endpoints, on-device/on-client inference, or monitoring of a live pipeline.
- Quantitative coursework (statistics, calculus) visible in Education; GPA on the page; `Expected May 2028` sits inside December 2027 – June 2028.
- C++ or Java through use is a plus, not a floor.

**Anti-patterns:**
- Research-lab / publications lead — this req is applied product ML (`recruiting.md` §13 applied vs research split).
- Notebook ML or `model.fit()` with no eval, no system, no delivery.
- Generic full-stack or club-ops occupying the lead while ML/LLM evidence is buried or Skills-only.
- Hard-real-time C++/audio-DSP as the first-pass identity on an LLM/product-ML intern req (systems depth can support, not lead).
- Invented Snowflake, Databricks, Copilot, Fusion, Tableau, Sentry, Hugging Face, LangChain, TensorFlow, or scikit-learn claims the page cannot defend (`resume.md` §8 fabrication smell).
- Skills-line PyTorch/LLMs with no backing system on the page.
- Vanity metrics (uptime, LOC, coverage %) standing in for impact.
